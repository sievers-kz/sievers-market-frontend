## Решения, которые не видны из кода
- **Сессия и прокси.** Бэкенд ставит cookie без `Domain`. Браузер ходит на свой origin `/api/v1/...`, rewrite в `next.config.ts` ведёт на `BACKEND_URL` (серверная переменная, читается при сборке; нужна в `.env.local` и в Vercel). Путь ровно `/api/v1`: refresh-cookie стоит с `Path=/api/v1/iam`. Нужен `skipTrailingSlashRedirect` (у части путей API слэш на конце). Сервер Next ходит на `BACKEND_URL` напрямую и пробрасывает `Cookie`.
- **Токен на сервере не обновляется** (Server Component не ставит cookie): `getCurrentUser()` при 401 даёт `null`. Single-flight refresh работает только в браузере. Серверное обновление через `proxy.ts` отложено.
- **`getCurrentUser()`** вызывает `getCustomerMe` (`GET /customer/me`) и возвращает `CustomerMeResponse | null` (`null` при 401). Профиль бэкенд создаёт сам при первом обращении. ФИО может быть `null`: буква аватара из имени или почты, в меню «Фамилия Имя» только если оба заданы.
- **После входа и подтверждения почты** ведём на `safeNextPath(next) ?? "/"` без запроса пользователя; авторизованного на `/login` и `/register` редиректим на `/`.
- **Группы маршрутов.** Страницы сайта лежат в `src/app/(site)/` (layout с `SiteHeader`), вход/регистрация/восстановление пароля в `(auth)` (только логотип, `MinimalHeader`). Новые страницы сайта класть в `(site)`. Корневая 404 (`_not-found`) идёт без шапки.
- **Пользователь в шапке читается в браузере** (`HeaderUserProvider`, клиентский `getCurrentUser()`, один запрос на блок пользователя и кнопку «Подать объявление»), а не на сервере: без `cacheComponents` вызов `cookies()` в layout делает динамическими все страницы под ним, `Suspense` от этого не спасает. Переход на Cache Components (PPR) отложен. Плюс: в браузере работает refresh, поэтому шапка не «теряет» пользователя после 30 минут.
- **shadcn CLI** при `add` подсовывает npm-пакет `cn` и импорт `from "cn"`: пакет удалять, импорт менять на `@/lib/utils`.
- **`NEXT_PUBLIC_API_URL`** остаётся только для картинок (`getMediaUrl`, `images.remotePatterns`).
- **Ошибки.** Бэкенд отдаёт `{error_code, message, detail, metadata}`; `metadata.field` это имя поля запроса. Ошибки Pydantic (422 `{detail: [{loc, msg}]}`) обрабатываем сырыми, без единого формата на бэкенде. Идея на потом: словарь `error_code → текст` с запасным `message` (в `error-codes.ts`).
- **Радио-плитки** (`TileRadioGroup`) сделаны настоящими `input type="radio"`; выбор не переключает шаг, дальше ведёт кнопка «Продолжить».
- **Цвета.** `primary` (#076852) фирменный: шапка, ссылки, фокус, выбранное. `cta` (#1C608A, белый текст) у главных действий: «Подать объявление», «Опубликовать». Токена `contact` больше нет.
- **Скелетоны.** `Skeleton` это полоска (`bg-primary/10` с бликом, без блика при `prefers-reduced-motion`), а не карточка. Белые карточки-заглушки делаются `SkeletonCard` или разметкой настоящей карточки, полоски кладутся внутрь. Заглушки повторяют раскладку страницы, чтобы контент не прыгал.
- **Каталог и смена фильтра.** `loading.tsx` на смену `searchParams` не срабатывает (граница привязана к сегменту `[categoryId]`). Список (`CatalogListings`) обёрнут в `Suspense` с `key` = URL каталога: при смене параметров монтируется новая граница со скелетоном, сайдбар не трогается. Проверка «страница больше числа страниц» живёт внутри `CatalogListings`.
- **Сетки на телефоне.** Сетка без шаблона колонок растягивается по самому широкому содержимому (строка подкатегорий, `truncate`): нужен `grid-cols-[minmax(0,1fr)]` / `grid-cols-1` и `min-w-0` у flex-элементов с обрезкой.
- **Курсор** задан в `globals.css` (`button`, `[role=button]`, `summary`, `select`; у отключённых `not-allowed`). `cursor-pointer` по компонентам не вешаем.
- **Поля ввода.** Фокус: рамка `primary` и `ring-2 ring-primary/30` у `Input`, `Textarea`, `SelectTrigger`, `Checkbox`. Фон полей `bg-card`, у отключённого селекта `bg-muted`.
- **Кнопка «Подать объявление»** (`PostListingButton`): гость → `/login?next=/listings/new`, вошедший и «ещё проверяем» → `/listings/new`. `ListingCreateGate` проверяет вход и наличие `verified` организации.
- **Деталка и 404.** `getListingDetails` обёрнут в `cache` в `page.tsx` (один запрос на metadata и страницу); 404, 422 и пустой ответ 200 → `notFound()`. Из-за `loading.tsx` ответ уже стримится, поэтому HTTP-статус «не найдено» 200 с `noindex` (так задумано в Next, в каталоге так же).
- **Деталка: раскладка.** Название, подкатегория и город вынесены в отдельную карточку `ListingTitleCard` над колонками; в карточке цены только цена, карточки продавца нет (данных организации в ответе нет, backend#207). Порядок блоков на телефоне задан через `order`: левая колонка на телефоне `contents`, с `lg` обычный flex.
- **Загрузка фото.** `PUT` в MinIO из браузера проверен 6 ноября 2026: CORS не мешает. Каждый файл идёт своей цепочкой `generateUploadUrl` → `uploadToPresignedUrl` → `confirmUpload` (`useImageUploads`), чтобы повторять и убирать файлы по одному.
- **Ошибки вложенных полей.** У `FieldError` есть `path` (весь `loc` без `body`, через точку); `applyApiErrorToForm` принимает `resolveField`. Так ошибка `attributes.<ключ>` попадает на поле атрибута, а не теряется по последнему элементу `loc`.
- **Форма создания.** Схема Zod собирается заново из `getSubcategoryForm` (`buildListingSchema`); числа в форме хранятся строками, в число превращает схема. Чекбоксы отправляются всегда (`true`/`false`), пустые необязательные поля не отправляются. Необязательный выбор имеет пункт «Не указано» (Radix Select не принимает пустое значение). `organization_id` есть в схеме Zod (`z.uuid`, «Выберите организацию»), но поле стоит вне `<form>`: выбор живёт в `ListingCreateFlow` (не сбрасывается сменой подкатегории), форма получает его пропсом и кладёт через `setValue`, а ошибку поля отдаёт наверх (`onOrganizationError`). Справочники для `reference` передаются словарём по `field.source` (`brand`, `color`, `country`). Смена подкатегории пересоздаёт форму (`key`), а фото остаются: `useImageUploads` живёт в `ListingCreateFlow` и передаётся в форму пропсом. Образец цвета в селекте только для `source: "color"`; `hex` приходит как `#367C2B`, проверяется `parseHexColor`. Id нового объявления берётся из `{ response: "<uuid>" }` (`getCreatedListingId`). Ограничения цены (> 0) и галереи (1–10) только из спецификации: в OpenAPI их нет.
- **Превью объявления.** `ListingCardView` рисует карточку без ссылки; `ListingCard` оборачивает её в `Link` (фокус, тень и `group` на ссылке). Пустые `title`/`price`/`city` дают приглушённые заглушки. Фото в карточке с отступом 8 (`p-2`) и своим `rounded-lg` (каталог и превью; `ListingCardSkeleton` повторяет); без фото иконка `ImageOff` 48 px, подпись под ней только при `imagePlaceholder` (в превью «Фото появится здесь»). Фото превью: первое `done` (та же «Обложка», что в загрузчике), `blob:` через обычный `img`. `ListingPreviewData` собирается во Flow: поля приходят из `ListingPreviewWatcher` (компонент без разметки внутри формы, `useWatch` по четырём полям), сброс к заглушкам в `loadForm`. Чтобы ввод не перерисовывал форму через Flow, `ListingForm` обёрнут в `memo`, `useImageUploads` отдаёт мемоизированный объект; все пропсы формы должны оставаться стабильными (колбэки через `useState`/`useCallback`).
- **Выбор организации.** Выбранный id выводится из списка (`resolveOrganizationId`): выбор пользователя, если он ещё `verified`, иначе единственная `verified`, иначе пусто. Ветка «форма или заглушка» решается один раз при загрузке: 404 `organization_not_found_error` / 403 `organization_cannot_publish_error` при публикации дают сообщение формы и тихо перечитывают список, форма остаётся (если подтверждённых не осталось, селект отключён с подписью «Нет подтверждённых организаций» и ссылкой «Мои организации»). Тексты заглушек и селекта лежат в самих компонентах (`organization-required.tsx`, `organization-select.tsx`), подпись типа из `KIND_LABELS`.
- **«Мои организации».** Отдельной проверки входа нет: `OrganizationsView` сразу зовёт `getOrganizations()` в браузере, 401 (уже после refresh) ведёт на `/login?next=/account/organizations`; так же 401 в опросе, добавлении и удалении. Все тексты и подписи статусов в `organization-labels.ts`. Опрос (`useRegistryStatusPolling`) живёт в каждой карточке `pending`: первый запрос через 3 с, скрытая вкладка не тратит попытки, «Проверить снова» спрашивает сразу. Новая организация добавляется в конец списка с `kind` и `tax_id` из формы, остальное приходит с опросом. Кнопка «Удалить» `ghost` с цветом `destructive` (вариант `destructive` у нас залитый).
- **shadcn `dialog`, `alert-dialog`, `badge`** подогнаны под проект: затемнение `bg-foreground/50` вместо `bg-black`, окна `rounded-2xl bg-card gap-6`, у бейджа `py-1`, «Close» → «Закрыть».
- **Каркас кабинета.** Страницы под `/account/*` не рисуют `<main>` и `Container` и ставят `AccountPageHeader` первым элементом; `loading.tsx` и `error.tsx` рендерятся в колонке контента. Карточку сайдбара рисует `<aside>` в `AccountShell` (только с `lg`), `AccountNav` один набор разметки: ниже `lg` строка вкладок (`-mx-4 px-4` на `aside`, прокрутка до краёв экрана, иконки скрыты). Пункты без страницы: `span role="link" aria-disabled="true"` вне табуляции; курсор `not-allowed` в `globals.css` для любого `[aria-disabled="true"]`. Бейдж «Скоро» `bg-muted text-foreground`: `muted-foreground` на `muted` даёт 4.39:1 (решение владельца, 11 ноября 2026).
- **Пользователь в контексте.** `HeaderUserProvider` поднят в `(site)/layout.tsx` и оборачивает шапку и страницы; в контексте `state`, `showGuest`, `setUser`. Статичность страниц не изменилась (сверено по выводу `npm run build` до и после; `/account` тоже статическая). `AccountUserBlock` читает контекст, своего запроса нет (на телефоне лишнего запроса больше нет): имя «Фамилия Имя» или «Пользователь», почта, обе строки `truncate` с `title`. Ошибка провайдера = `null`, блок не показывается. Инициалы `getAvatarInitials` (имя + фамилия) в `user-display.ts`.
- **Страница «Аккаунт».** Пользователя читает сама (`getCurrentUser()`; на `/account` два запроса `getCustomerMe`: провайдер и страница), потому что ей нужны «ошибка» и «Повторить». После правки сначала показывает отправленные значения, затем перечитывает пользователя; оба раза отдаёт его в `setUser`, шапка и сайдбар меняются сразу. Ошибка перечитывания (сеть, 5xx) не показывается. Диалоги пересоздаются на каждое открытие (`key`), закрыть во время запроса нельзя. Шаги почты и пароля локальные; «код устарел» возвращает на шаг 1 с сообщением формы (у почты с введённым адресом, у пароля с пустыми полями). Пароли для повторной отправки держит только шаг диалога. После смены пароля `router.replace("/login?next=%2Faccount&reason=password-changed")` и `refresh()`: бэкенд сам завершает сессию. `password_mismatch_error` показываем своим текстом «Неверный текущий пароль». Правила ФИО в Zod из бэкенда (в OpenAPI их нет), пробелы обрезаем и схлопываем, пустое отчество уходит `null`.
- **Активный пункт сайдбара.** `isAccountNavItemActive(pathname, href, exact)`: у пункта с `exact: true` («Аккаунт») только точное совпадение, иначе он горел бы на всех страницах кабинета.
- **`?reason=` на входе.** Текст берётся из словаря (`login-reason.ts`, `Object.hasOwn`), значение из адреса не выводится, неизвестное игнорируется. Сейчас одно значение: `password-changed`.
- **Повторная отправка кода.** Отсчёт `useResendCooldown` (`src/hooks/`, 60 с с момента показа шага) и ячейки `ConfirmCodeInput` (`components/auth/`) общие для регистрации и диалогов аккаунта; поведение регистрации прежнее (проверено в браузере). Схемы кода и нового пароля (`confirmCodeValue`, `newPasswordValue`) в `auth/schemas.ts`.
- **Карточка организации.** Меню «⋯» на `DropdownMenu modal={false}`, `DeleteOrganizationDialog` управляемый (`open`/`onOpenChange`) и без своей кнопки: так `AlertDialog` открывается из пункта меню без зависшего `pointer-events: none` на `body`. Сообщение «Подтверждённую организацию удалить нельзя» осталось строкой в карточке: в новой спеке места для него нет. Текст пустого состояния разделён на `emptyTitle` и `empty`.
- **Публичные запросы без cookie.** `apiFetch` на сервере зовёт `cookies()`, а это делает динамической каждую страницу с запросом, в том числе через общий layout. Для публичных справочников опция `forwardCookies: false` (сейчас у `getCategoryTree`). Так шапка читает дерево, а `/`, `/privacy`, `/terms`, `/account/organizations` остаются статическими (ISR 1 ч по `revalidate` дерева). Новым справочникам, которые вызываются из layout или статических страниц, ставь эту опцию.
- **Мега-меню.** Якорь `Popover` это весь нижний ряд шапки (ширина панели = ряд, 1248 на 1280), поэтому поиск и «Подать объявление» передаются в `CatalogMegaMenu` через `children`. Закрытие при навигации: `useCloseOnNavigation` (смена `pathname` + `popstate`; `useSearchParams` в шапке потребовал бы `Suspense` и убрал бы кнопку из статического HTML). Ссылки меню не попадают в HTML страницы: содержимое `Popover`/`Dialog` рисуется только при открытии. Если дерево упало при сборке или ревалидации, страница до часа хранит «Каталог временно недоступен».
- **Страница организации.** Все тексты в `ORGANIZATION_DETAIL_TEXT`, подписи полей магазина в `SHOP_FIELD_LABELS` (`organization-labels.ts`). Подсказка (`OrganizationNotice`) по `registry_status` и `missing_fields` (список считает бэкенд, на фронте по `null` не пересчитываем). Состояния страницы: загрузка, ошибка с «Повторить», «Организация не найдена» (404 и 422 на кривой id; карточка без «Назад», вместо неё кнопка «К моим организациям»). Сообщение «Подтверждённую организацию удалить нельзя» (400 при удалении) строкой внизу шапки-карточки, как в списке.
- **Правка полей.** Диалог пересоздаётся на каждое открытие (`key`), форма всегда из одного поля `value`; ошибки бэкенда сводятся к нему (`resolveField` по имени поля, `byErrorCode` для `invalid_shop_name_error` и `invalid_phone_format_error`). Тело ответа 200 не читаем: сначала подставляем отправленное значение, затем перечитываем `getOrganization` (телефон бэкенд нормализует, `missing_fields` пересчитывает). Ошибка перечитывания не показывается, остаются прежние данные. Правила из описаний операций: название 2–50 символов после схлопывания пробелов и хотя бы одна буква; телефон непустой (формат проверяет бэкенд); email до 255.
- **Опрос статуса** (`useRegistryStatusPolling`) отдаёт полную `OrganizationDetails` и принимает `loginPath`; список берёт из неё свои поля. `DeleteOrganizationDialog` получил необязательные `onNotFound` (по умолчанию как `onDeleted`) и `loginPath`. Путь входа строит `getLoginPath(next)` (`login-path.ts`).
- **Фокус после диалогов.** Radix `Dialog`/`AlertDialog` без `Trigger` при закрытии фокусирует пустой `triggerRef`, и фокус уходил на `body` (в том числе в списке после диалога удаления). Теперь `onCloseAutoFocus={returnFocusTo(ref)}` (`return-focus.ts`): фокус возвращается на кнопку «Изменить»/«Заполнить» или на «⋯». Новым диалогам, которые открываются не своим `Trigger`, делать так же.
- **Карточка-ссылка в списке.** `Link` в заголовке с `after:absolute after:inset-0`, кольцо фокуса на псевдоэлементе; меню «⋯» в обёртке `relative z-10`, не внутри `<a>`.
- **Тег `pending`** `bg-muted text-foreground`, а не `text-muted-foreground` из спеки: на `muted` это 4.39:1 (как у бейджа «Скоро»).
- **Неполный профиль организации.** Данные выбранной организации читает `useOrganizationDetails` (`getOrganization`, `no-store`, отмена прошлого запроса, без кэша между выборами; 404 → `onOrganizationsStale()`). Правило «чего не хватает» только из `missing_fields`, значения на `null` не проверяем (их пустоту показываем как «Не указано», но решение не меняют). Ошибка «Заполните данные магазина в организации, затем повторите отправку.» — это ошибка поля `organization_id` с `type` = `organization_profile_incomplete_error`: ставится в форме при «Опубликовать», если `missing_fields` непустой (запрос не уходит, показывается вместе с прочими ошибками), и после 403 (плюс тихое перечитывание данных). Flow по `type` отдаёт текст в `OrganizationSummary` (сообщение под полями, красные рамки у полей из `missing_fields`); карточка краснеет при любой ошибке `organization_id`, а селект красный только при «Выберите организацию» (при «не хватает данных» у него лишь `aria-describedby`). Снимается при выборе другой организации (перепроверка поля) или когда `missing_fields` становится пустым — только на переходе «был непустой → пуст», чтобы после 403 при устаревших «полных» данных ошибка не пропала сразу. Пока `missing_fields` непустой, данные тихо перечитываются на `visibilitychange` → `visible`. Ссылка на организацию открывается в новой вкладке: форма и фото не теряются. Остальные ошибки организации (404, 403 `organization_cannot_publish_error`) по-прежнему сообщением формы.
- **«Мои объявления».** URL единственный источник фильтров: `MyListingsView` читает `useSearchParams` (страница в `Suspense`), фильтры меняют URL через `router.replace({ scroll: false })` и сбрасывают `page`; пагинация обычными ссылками (push, прокрутка наверх: решение владельца, 16 ноября 2026). Ответ хранится с ключом запроса (URL + номер попытки): пока ключ не совпал, старый список приглушён (`aria-busy`), прошлый запрос отменяется `AbortController`. Страница статическая (ISR по дереву категорий). Организации для фильтра: ошибка, кроме 401, просто прячет фильтр. В пустом состоянии «нет объявлений вообще» (`total = 0` без статуса, организации и категории) панель фильтров тоже скрыта, не только кнопка в заголовке. Страница вне диапазона (`page > pages`) даёт «Ничего не найдено» с пагинацией. 422 без параметров в URL — «Ошибка списка» (чтобы не зациклиться). Расхождения OpenAPI со спекой: `currency` nullable → число без валюты; `status` типа `ListingStatus` (с `deleted`) → карточки `deleted` отбрасываются на клиенте (решения владельца, 16 ноября 2026).
- **Действия над объявлением.** Запросы, сообщения и перечитывание в `MyListingsView` (`runAction`), меню и диалог только вызывают `onAction` (не бросает). Одно действие за раз: на время действия и перечитывания списка все «⋯» `aria-disabled` (не `disabled`, иначе фокус после закрытия меню уходит на `body`); меню не открывается, потому что триггер отменяет `pointerdown` и Enter/пробел/стрелку вниз (Radix смотрит `defaultPrevented`). Сообщение хранит URL, на котором появилось, и видно только на нём (смена фильтра, страницы, «назад» его прячут), плюс сбрасывается в обработчиках фильтров. Удаление последней карточки не на первой странице ведёт на предыдущую (`router.replace`), сообщение привязано к её URL. Ошибка удаления закрывает диалог и показывается над списком, как у остальных действий (в отличие от удаления организации, где ошибка внутри диалога). 404/409 узнаём по статусу и коду вместе, остальное — «Не удалось выполнить действие». Кнопка «⋯» ниже `sm` в углу фото на `bg-card`, от `sm` в углу текстовой колонки (один `absolute`-блок в карточке, у колонки `sm:pr-12`). Сообщение `py-2 pr-2 pl-4` с кнопкой закрытия 40 вместо `py-3` из спеки (сетка 8pt).
- **Правила пароля:** 8-64 символа (регистрация); код подтверждения 6 цифр, живёт 5 минут; повтор не раньше чем через 60 секунд (на фронтенде константа, backend#203).

- **SEO и индексация.** Индексируется только сборка с `VERCEL_ENV=production` (`isIndexable()` в `src/lib/site.ts`); staging и preview закрыты (`Disallow: /` в `robots.txt`, `noindex` в корневых метаданных, пустой sitemap). Личные страницы production закрыты метатегом `noindex`, а не запретом в `robots.txt`: робот не прочитает метатег на запрещённой странице. Адрес сайта по умолчанию `https://market.sievers.kz`, можно переопределить `NEXT_PUBLIC_SITE_URL`. Sitemap: главная, категории, объявления (по страницам каталога, ISR 1 ч, сбой API не роняет сборку); подкатегории и страницы организаций пока не включены. Canonical у каталога без `?page=` и фильтров.
- **Дата и состояние в карточке каталога.** Дата всегда в поясе `Asia/Almaty` (и год тоже), явно в `Intl.DateTimeFormat`: иначе сервер (UTC) и браузер расходятся на границе суток. Слов «сегодня» и «вчера» нет: страница кэшируется, и они устаревают. Год показывается, только если он не текущий (в Алматы). Ключ состояния проверяется через `Object.hasOwn` по словарю `new`/`used`; неизвестный ключ, `null` и пустая строка означают, что тега нет. Бэкенд отдаёт `created_at` с `Z` (проверено на стенде 17 ноября 2026).
- **Фильтры каталога.** Разбор в два шага: `parseCatalogParams` проверяет форму (цена: цифры, безопасное целое, `min > max` меняются местами; `city` uuid; `sort` только `price_asc`/`price_desc`, `newest` = нет параметра), `sanitizeCatalogParams` на странице отсекает `f.*` без подкатегории, с ключом не из `getSubcategoryFilters` (и типов `integer`, `float`, `string`: в PR 1 их не рисуем), значением не из `options`/справочника, `boolean` не `true`, а город не из справочника (если он загрузился). Дальше все ссылки, чипы и `key` у `Suspense` строятся из очищенных параметров. Запрос: без фильтров и сортировки `getListingsCatalog`, иначе `searchListing` (`category_id` всегда, `no-store`, без cookie); 422 поиска = пустое состояние с фильтрами. Галочка уходит в `attributes` булевым `true`, `reference` — id из справочника, как в форме объявления. Сбой `getSubcategoryFilters` или справочника прячет атрибуты (поле), сбой городов прячет выбор города. Все три «сброса» (кнопка в панели, ссылка у чипов, кнопка в пустом состоянии) это одна `resetCatalogFilters`: убирают цену, город, `f.*` и сортировку, оставляют подкатегорию и вид. Смена подкатегории (`withSubcategory`) убирает только `f.*`. Число на кнопке «Фильтры · N» = число чипов (сортировка не считается).
- **Ключи соседей.** У `CatalogFiltersDialog` нет `key`: с тем же `key`, что у соседнего `Suspense`, React оставлял старый экземпляр в DOM и диалог не закрывался после «Показать». Форма в диалоге и так монтируется при каждом открытии; панель в сайдбаре пересоздаётся `key` = URL (другой родитель).

## Известные ограничения и долги
- Шапка: поиск заглушка; «Подать объявление» на телефоне скрыто; меню аватара: «Мои организации», «Мои объявления», «Выйти» (избранного нет; пункт «Аккаунт» в меню не добавлен, решение за владельцем).
- Выбор организации: дизайн не утверждён (Figma «Frame 848» ориентир), сделан shadcn `Select` по умолчанию. PR 3 не проверен руками с учёткой на стенде (три ветки заглушек, выбор из нескольких, 404/403 при публикации); проверены `typecheck`, `lint`, `build` и серверный рендер `/listings/new` со справочниками.
- Вход и регистрация могут потерять 422 с полем вне формы (решается опцией `fields` в `showFormError`).
- Тупик на шаге кода при закрытой странице (backend#202).
- Картинки объявлений не видны: бэкенд подписывает ссылки внутренним хостом MinIO (backend#208).
- Расхождения OpenAPI для создания (Issue ещё не заведён): у `createListing` пустая схема ответа (`unknown`), у `AttributeFieldResponse` `options` и `unit` произвольные словари.
- Деталка: подписи характеристик это ключи (`getAttributeLabel`, TODO); значения выводятся сырыми (`brand` uuid, `condition: used`); массивы и объекты пропускаются. Хлебные крошки без рубрики и категории (backend#217).
- Превью карточки на телефоне не показывается (`hidden lg:flex`): по спеке её место между аккордеонами и кнопкой внутри `<form>`, это потребовало бы второго экземпляра. Превью не проверено руками в браузере с учёткой. Каталог («плитка» и «список», 375 и десктоп) после выноса `ListingCardView` и отступа у фото сверен руками.
- Создание: убранные пользователем фото остаются в хранилище без объявления. Форма на ширине 375 не проверена руками. `reference` с неизвестным `source` показывается недоступным выбором. Не проверено руками: ошибки бэкенда по атрибутам, смена подкатегории с заполненной формой, больше 10 фото, файл больше 5 МБ.
- Чекбоксы (регистрация, атрибуты) 16 × 16: кликабельна подпись, но сама область меньше 40 px.
- «Мои организации» не проверены руками с учёткой на стенде (добавление, опрос до `verified`/`not_found`, удаление, 409); проверены только `typecheck`, `lint`, `build`. В OpenAPI у `tax_id` нет `pattern` (12 цифр только в описании), у операций организаций нет 401.
- Каркас кабинета проверен в Chromium (Playwright из scratchpad, в проект не добавлен) на 375, 768, 1280, 1440 с подменой ответов API (список, пусто, ошибка, меню и диалог удаления); с учёткой на стенде не проверен.
- Сайдбар 304: подпись рядом с бейджем «Скоро» обрезается `truncate` (у «Моих объявлений» бейджа больше нет). Если мешает, править плотность, а не шрифт.
- «Мои объявления» проверены в Chromium (Playwright из scratchpad, библиотеки `libnss3` и др. распакованы туда из `.deb` без установки) на 375, 768, 1280, 1440 с подменой ответов API: список со всеми статусами и пустыми полями, вкладки и URL, сортировка, категория, «Сбросить фильтры», приглушённый список при медленном ответе, пусто, ошибка и «Повторить», 404 по организации, 422, фокус на карточке. С учёткой на стенде не проверены. Картинки карточек не проверены (backend#208). В OpenAPI у `getMyListings` нет 401 и схемы тела 404.
- Действия в «Моих объявлениях» проверены в Chromium (Playwright из scratchpad) на 375, 768, 1280 с подменой ответов API: пункты по статусу, клик по «⋯» не открывает объявление, занятость и блокировка остальных «⋯», перечитывание, сообщения, 500/404/409/401, диалог (отмена, «Удаляем…», фокус), удаление последней карточки на странице 2, сброс сообщения при смене фильтра. С учёткой на стенде не проверены. Если после действия карточка уходит из выбранной вкладки, фокус клавиатуры теряется (уходит на `body`) вместе с кнопкой. В OpenAPI у четырёх операций ответ 200 `unknown` (по спеке `{ message }`; тело не читаем) и нет 401.
- Мега-меню проверено в Chromium (Playwright из scratchpad) на 1280 и 375 с бэкендом стенда (одна рубрика) и с подменой дерева (пусто, ошибка сети и 500, три рубрики, длинный список).
