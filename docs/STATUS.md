## Решения, которые не видны из кода
- **Сессия и прокси.** Бэкенд ставит cookie без `Domain`. Браузер ходит на свой origin `/api/v1/...`, rewrite в `next.config.ts` ведёт на `BACKEND_URL` (серверная переменная, читается при сборке; нужна в `.env.local` и в Vercel). Путь ровно `/api/v1`: refresh-cookie стоит с `Path=/api/v1/iam`. Нужен `skipTrailingSlashRedirect` (у части путей API слэш на конце). Сервер Next ходит на `BACKEND_URL` напрямую и пробрасывает `Cookie`.
- **Токен на сервере не обновляется** (Server Component не ставит cookie): `getCurrentUser()` при 401 даёт `null`. Single-flight refresh работает только в браузере. Серверное обновление через `proxy.ts` отложено.
- **`getCurrentUser()`** вызывает `getCustomerMe` (`GET /customer/me`) и возвращает `CustomerMeResponse | null` (`null` при 401). Профиль бэкенд создаёт сам при первом обращении. ФИО может быть `null`: буква аватара из имени или почты, в меню «Фамилия Имя» только если оба заданы.
- **После входа и подтверждения почты** ведём на `safeNextPath(next) ?? "/"` без запроса пользователя; авторизованного на `/login` и `/register` редиректим на `/`.
- **Группы маршрутов.** Страницы сайта лежат в `src/app/(site)/` (layout с `SiteHeader`), вход/регистрация/восстановление пароля в `(auth)` (только логотип, `MinimalHeader`). Новые страницы сайта класть в `(site)`. Корневая 404 (`_not-found`) идёт без шапки.
- **Пользователь в шапке читается в браузере** (`HeaderUserProvider`, клиентский `getCurrentUser()`, один запрос на блок пользователя и кнопку «Подать объявление»), а не на сервере: без `cacheComponents` вызов `cookies()` в layout делает динамическими все страницы под ним, `Suspense` от этого не спасает. Переход на Cache Components (PPR) отложен. Плюс: в браузере работает refresh, поэтому шапка не «теряет» пользователя после 30 минут.
- **shadcn CLI** при `add` подсовывает npm-пакет `cn` и импорт `from "cn"`: пакет удалять, импорт менять на `@/lib/utils`.
- **`NEXT_PUBLIC_API_URL`** остаётся только для картинок (`getMediaUrl`, `images.remotePatterns`).
- **Ошибки.** Бэкенд отдаёт `{error_code, message, detail, metadata}`; `metadata.field` это имя поля запроса. Ошибки Pydantic (422 `{detail: [{loc, msg}]}`) обрабатываем сырыми, без единого формата на бэкенде. Идея на потом: словарь `error_code → текст` с запасным `message` (в `error-codes.ts`).
- **Радио-плитки** (`TileRadioGroup`) сделаны настоящими `input type="radio"`; выбор не переключает шаг, дальше ведёт кнопка «Продолжить».
- **Цвета.** `primary` (#076852) фирменный: шапка, ссылки, фокус, выбранное. `cta` (#1C608A, белый текст) у главных действий: «Подать объявление», «Опубликовать». Токена `contact` больше нет.
- **Скелетоны.** `Skeleton` это полоска (`bg-primary/10` с бликом, без блика при `prefers-reduced-motion`), а не карточка. Белые карточки-заглушки делаются `SkeletonCard` или разметкой настоящей карточки, полоски кладутся внутрь. Заглушки повторяют раскладку страницы, чтобы контент не прыгал.
- **Каталог и смена фильтра.** `loading.tsx` на смену `searchParams` не срабатывает (граница привязана к сегменту `[categoryId]`). Список (`CatalogListings`) обёрнут в `Suspense` с `key` = URL каталога: при смене параметров монтируется новая граница со скелетоном, сайдбар не трогается. Проверка «страница больше числа страниц» живёт внутри `CatalogListings`.
- **Сетки на телефоне.** Сетка без шаблона колонок растягивается по самому широкому содержимому (строка подкатегорий, `truncate`): нужен `grid-cols-[minmax(0,1fr)]` / `grid-cols-1` и `min-w-0` у flex-элементов с обрезкой.
- **Курсор** задан в `globals.css` (`button`, `[role=button]`, `summary`, `select`; у отключённых `not-allowed`). `cursor-pointer` по компонентам не вешаем.
- **Поля ввода.** Фокус: рамка `primary` и `ring-2 ring-primary/30` у `Input`, `Textarea`, `SelectTrigger`, `Checkbox`. Фон полей `bg-card`, у отключённого селекта `bg-muted`.
- **Кнопка «Подать объявление»** (`PostListingButton`): гость → `/login?next=/listings/new`, вошедший и «ещё проверяем» → `/listings/new`. `ListingCreateGate` проверяет вход и наличие `verified` организации.
- **Деталка и 404.** `getListingDetails` обёрнут в `cache` в `page.tsx` (один запрос на metadata и страницу); 404, 422 и пустой ответ 200 → `notFound()`. Из-за `loading.tsx` ответ уже стримится, поэтому HTTP-статус «не найдено» 200 с `noindex` (так задумано в Next, в каталоге так же).
- **Деталка: раскладка.** Название, подкатегория и город вынесены в отдельную карточку `ListingTitleCard` над колонками; в карточке цены только цена, карточки продавца нет (данных организации в ответе нет, backend#207). Порядок блоков на телефоне задан через `order`: левая колонка на телефоне `contents`, с `lg` обычный flex.
- **Загрузка фото.** `PUT` в MinIO из браузера проверен 6 ноября 2026: CORS не мешает. Каждый файл идёт своей цепочкой `generateUploadUrl` → `uploadToPresignedUrl` → `confirmUpload` (`useImageUploads`), чтобы повторять и убирать файлы по одному.
- **Ошибки вложенных полей.** У `FieldError` есть `path` (весь `loc` без `body`, через точку); `applyApiErrorToForm` принимает `resolveField`. Так ошибка `attributes.<ключ>` попадает на поле атрибута, а не теряется по последнему элементу `loc`.
- **Форма создания.** Схема Zod собирается заново из `getSubcategoryForm` (`buildListingSchema`); числа в форме хранятся строками, в число превращает схема. Чекбоксы отправляются всегда (`true`/`false`), пустые необязательные поля не отправляются. Необязательный выбор имеет пункт «Не указано» (Radix Select не принимает пустое значение). `organization_id` есть в схеме Zod (`z.uuid`, «Выберите организацию»), но поле стоит вне `<form>`: выбор живёт в `ListingCreateFlow` (не сбрасывается сменой подкатегории), форма получает его пропсом и кладёт через `setValue`, а ошибку поля отдаёт наверх (`onOrganizationError`). Справочники для `reference` передаются словарём по `field.source` (`brand`, `color`, `country`). Смена подкатегории пересоздаёт форму (`key`), а фото остаются: `useImageUploads` живёт в `ListingCreateFlow` и передаётся в форму пропсом. Образец цвета в селекте только для `source: "color"`; `hex` приходит как `#367C2B`, проверяется `parseHexColor`. Id нового объявления берётся из `{ response: "<uuid>" }` (`getCreatedListingId`). Ограничения цены (> 0) и галереи (1–10) только из спецификации: в OpenAPI их нет.
- **Превью объявления.** `ListingCardView` рисует карточку без ссылки; `ListingCard` оборачивает её в `Link` (фокус, тень и `group` на ссылке). Пустые `title`/`price`/`city` дают приглушённые заглушки. Фото в карточке с отступом 8 (`p-2`) и своим `rounded-lg` (каталог и превью; `ListingCardSkeleton` повторяет); без фото иконка `ImageOff` 48 px, подпись под ней только при `imagePlaceholder` (в превью «Фото появится здесь»). Фото превью: первое `done` (та же «Обложка», что в загрузчике), `blob:` через обычный `img`. `ListingPreviewData` собирается во Flow: поля приходят из `ListingPreviewWatcher` (компонент без разметки внутри формы, `useWatch` по четырём полям), сброс к заглушкам в `loadForm`. Чтобы ввод не перерисовывал форму через Flow, `ListingForm` обёрнут в `memo`, `useImageUploads` отдаёт мемоизированный объект; все пропсы формы должны оставаться стабильными (колбэки через `useState`/`useCallback`).
- **Выбор организации.** Выбранный id выводится из списка (`resolveOrganizationId`): выбор пользователя, если он ещё `verified`, иначе единственная `verified`, иначе пусто. Ветка «форма или заглушка» решается один раз при загрузке: 404 `organization_not_found_error` / 403 `organization_cannot_publish_error` при публикации дают сообщение формы и тихо перечитывают список, форма остаётся (если подтверждённых не осталось, селект отключён с подписью «Нет подтверждённых организаций» и ссылкой «Мои организации»). Тексты заглушек и селекта лежат в самих компонентах (`organization-required.tsx`, `organization-select.tsx`), подпись типа из `KIND_LABELS`.
- **«Мои организации».** Отдельной проверки входа нет: `OrganizationsView` сразу зовёт `getOrganizations()` в браузере, 401 (уже после refresh) ведёт на `/login?next=/account/organizations`; так же 401 в опросе, добавлении и удалении. Все тексты и подписи статусов в `organization-labels.ts`. Опрос (`useRegistryStatusPolling`) живёт в каждой карточке `pending`: первый запрос через 3 с, скрытая вкладка не тратит попытки, «Проверить снова» спрашивает сразу. Новая организация добавляется в конец списка с `kind` и `tax_id` из формы, остальное приходит с опросом. Кнопка «Удалить» `ghost` с цветом `destructive` (вариант `destructive` у нас залитый).
- **shadcn `dialog`, `alert-dialog`, `badge`** подогнаны под проект: затемнение `bg-foreground/50` вместо `bg-black`, окна `rounded-2xl bg-card gap-6`, у бейджа `py-1`, «Close» → «Закрыть».
- **Правила пароля:** 8-64 символа (регистрация); код подтверждения 6 цифр, живёт 5 минут; повтор не раньше чем через 60 секунд (на фронтенде константа, backend#203).

## Известные ограничения и долги
- Шапка: «Каталог» и поиск заглушки; «Подать объявление» на телефоне скрыто; меню аватара: «Мои организации» и «Выйти».
- Выбор организации: дизайн не утверждён (Figma «Frame 848» ориентир), сделан shadcn `Select` по умолчанию. PR 3 не проверен руками с учёткой на стенде (три ветки заглушек, выбор из нескольких, 404/403 при публикации); проверены `typecheck`, `lint`, `build` и серверный рендер `/listings/new` со справочниками.
- Вход и регистрация могут потерять 422 с полем вне формы (решается опцией `fields` в `showFormError`).
- Тупик на шаге кода при закрытой странице (backend#202).
- Картинки объявлений не видны: бэкенд подписывает ссылки внутренним хостом MinIO (backend#208).
- Расхождения OpenAPI для создания (Issue ещё не заведён): у `createListing` пустая схема ответа (`unknown`), у `AttributeFieldResponse` `options` и `unit` произвольные словари.
- Деталка: подписи характеристик это ключи (`getAttributeLabel`, TODO); значения выводятся сырыми (`brand` uuid, `condition: used`); массивы и объекты пропускаются. Хлебные крошки без рубрики и категории (backend#217).
- Превью карточки на телефоне не показывается (`hidden lg:flex`): по спеке её место между аккордеонами и кнопкой внутри `<form>`, это потребовало бы второго экземпляра. Превью не проверено руками в браузере с учёткой. Каталог («плитка» и «список», 375 и десктоп) после выноса `ListingCardView` и отступа у фото сверен руками.
- Создание: убранные пользователем фото остаются в хранилище без объявления. Форма на ширине 375 не проверена руками. `reference` с неизвестным `source` показывается недоступным выбором. Не проверено руками: ошибки бэкенда по атрибутам, смена подкатегории с заполненной формой, больше 10 фото, файл больше 5 МБ.
- Чекбоксы (регистрация, атрибуты) 16 × 16: кликабельна подпись, но сама область меньше 40 px.
- «Мои организации» не проверены руками с учёткой на стенде (добавление, опрос до `verified`/`not_found`, удаление, 409); проверены только `typecheck`, `lint`, `build`. В OpenAPI у `tax_id` нет `pattern` (12 цифр только в описании), у операций организаций нет 401.
- Тестов в проекте нет.
- Vercel не подключён.
