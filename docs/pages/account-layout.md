# Каркас личного кабинета

- **Маршрут:** всё под `/account/*` (сейчас `/account/organizations`; позже «Мои объявления», «Избранное», «Профиль»).
- **Доступ:** авторизованный. Проверку входа по-прежнему делает каждая страница в браузере (как `OrganizationsView`); каркас пользователя не запрашивает и от входа не зависит.
- **Макет:** Design-холст https://claude.ai/artifact/51mfXuveEn6dy6rpdCpEpU (артборды «A · плавающий сайдбар», «A · нет организаций», «Кабинет · телефон»). Это **визуальный ориентир**: размеры подгоняй под сетку 8pt и токены.
- **Контекст:** прочитай `docs/pages/organizations.md` (страница, которая переезжает в каркас) и `docs/pages/header.md`.

Это PR «каркас»: сайдбар, раскладка и перенос в неё «Мои организации». Новых разделов не добавляем.

## Решение по раскладке
Выбран вариант A: **плавающий сайдбар-карточка внутри обычного `Container` (1280)** на светло-серой странице; справа колонка белых карточек. Исключения из правила про `Container` нет: левый край сайдбара совпадает с логотипом в шапке. Слитный сайдбар (вариант B) и контент на всю ширину отклонены. Решение рабочее, пересмотрим по живой странице; поэтому сайдбар живёт в одном компоненте и вид меняется правкой классов, не страниц.

## Структура файлов
```
src/app/(site)/account/layout.tsx     каркас для всех страниц кабинета
src/components/account/account-shell.tsx    раскладка (сайдбар + колонка контента)
src/components/account/account-nav.tsx      "use client": навигация (usePathname)
src/components/account/account-nav-items.ts конфигурация пунктов
src/components/account/account-page-header.tsx  белая карточка с заголовком страницы
```
`layout.tsx` остаётся тонким (Server Component, без запросов): рендерит `AccountShell`. Страницы кабинета больше **не** оборачиваются в свой `<main>` и `Container`: это делает каркас.

## Раскладка
- Страница: `<main className="flex-1 bg-muted py-6 lg:py-8">` → `<Container>` → колонки.
- `lg` и выше: две колонки, `flex gap-6 items-start`: сайдбар шириной 256 (`w-64`, не сжимается), справа `min-w-0 flex-1`, внутри колонка с зазором 16 (`flex flex-col gap-4`).
- Ниже `lg`: одна колонка (`flex-col gap-4`): вкладки, затем контент.
- Контент не ограничиваем по ширине внутри колонки: карточки занимают всю ширину.

### Сайдбар (`lg+`)
- `<nav aria-label="Личный кабинет">`, карточка `rounded-2xl bg-card p-4`, `self-start` (по высоте контента, не тянется).
- Заголовок группы не нужен (пунктов мало). Данные сразу в виде **групп**: `AccountNavGroup[]`, каждая группа массив пунктов; между группами тонкий разделитель (`border-t border-border`, отступы 8). Сейчас группа одна, разделитель не рисуется.
- Пункт: высота 48 (`h-12`), `rounded-lg px-4`, иконка 20 (lucide) + подпись, зазор 16.
  - активный (`pathname` совпадает с `href` или начинается с `href + "/"`): `bg-accent text-accent-foreground font-semibold`, `aria-current="page"`;
  - обычный: `text-foreground`, ховер `hover:bg-muted`;
  - **без страницы** (`href: null`): не ссылка, `aria-disabled="true"`, цвет `text-muted-foreground`, справа бейдж «Скоро» (`bg-muted`, 12px, `rounded-full px-2 py-0.5`), не фокусируется, курсор `not-allowed` (задан глобально для `[aria-disabled]` не вешай вручную: проверь `globals.css`, если не покрыто — добавь одно правило там).
- Пункты (конфиг в `account-nav-items.ts`, тексты там же): «Мои организации» (`/account/organizations`, иконка `Building2`), «Мои объявления» (`null`, `FileText`), «Избранное» (`null`, `Heart`), «Профиль» (`null`, `User`).
- Блока пользователя (аватар, имя) в сайдбаре **нет**: он уже в шапке.

### Вкладки (ниже `lg`)
Тот же компонент `AccountNav`, другая раскладка (через классы, не два набора разметки): горизонтальная строка `flex gap-2 overflow-x-auto`, полоса прокрутки скрыта (`[scrollbar-width:none]`, `[&::-webkit-scrollbar]:hidden`), края к краю экрана с отступом `px-4` (через отрицательные поля контейнера или внутренний padding, чтобы прокрутка шла до края экрана). Вкладка: `h-10 shrink-0 rounded-full px-4`, активная `bg-accent text-accent-foreground`, остальные `bg-card`; «Скоро» отключённые так же, бейдж внутри вкладки. Активная вкладка при загрузке прокручивается в видимую область (`scrollIntoView({ inline: "center", block: "nearest" })` в эффекте, без анимации).

### Заголовок страницы (`AccountPageHeader`)
Props: `title: string`, `action?: ReactNode`. Белая карточка `rounded-2xl bg-card px-8 py-6` (на телефоне `px-4 py-4`), `h1` `text-2xl lg:text-3xl font-semibold`, справа `action` (на телефоне действие под заголовком на всю ширину, как сейчас). Каждая страница кабинета ставит его первым элементом.

## Перенос «Мои организации»
Страница `docs/pages/organizations.md` едет в каркас; остальная логика не меняется.
- `page.tsx`, `loading.tsx`, `error.tsx`: убрать `<main>` и `Container`, оставить содержимое. Они рендерятся в колонке контента, сайдбар при загрузке и ошибке остаётся на месте.
- Заголовок и кнопку «Добавить организацию» собрать на `AccountPageHeader` (`action` = кнопка `cta`).
- Список **одной колонкой** на всех ширинах (убрать `lg:grid-cols-2`), зазор 16. Карточка организации: на `sm+` одна строка: слева название и тип/номер, справа бейдж статуса и «Удалить»; подсказка статуса под разделителем (`border-t`, отступ 16) на всю ширину. На телефоне всё в столбик: бейдж, название, тип/номер, подсказка, «Удалить». Внутренние отступы карточки `px-8 py-6` на `sm+`, `p-4` на телефоне.
- Пустое состояние: белая карточка по центру (иконка `Building2` в круге `bg-accent` 64, заголовок «У вас пока нет организаций», текст из `ORGANIZATIONS_TEXT.empty`, кнопка «Добавить организацию»); кнопку в `AccountPageHeader` в этом состоянии не показывай, чтобы не дублировать.
- Скелетон списка повторяет новую раскладку (одна колонка полосок внутри белых карточек).
- Меню аватара в шапке: пункт «Мои организации» остаётся; другие пункты добавляем только когда у них появятся страницы.

## Состояния
- Загрузка, ошибка, пусто: каждая страница отдаёт свои, каркас остаётся неизменным.
- 404 внутри `/account/*` (`notFound()`): общая 404.

## Адаптивность и доступность
Проверь 375, 768, 1280 и 1440: сайдбар не прыгает, вкладки прокручиваются, отключённые пункты недоступны с клавиатуры, активный пункт виден и озвучивается (`aria-current`). Фокус виден (`focus-visible` кольцо `primary`). Контраст «Скоро» и серых подписей не ниже 4.5:1 (`muted-foreground` на `card`).

## Что не делаем
Сами страницы «Мои объявления», «Избранное», «Профиль»; блок пользователя и хлебные крошки; сворачивание сайдбара; счётчики и бейджи уведомлений; общая смена ширины `Container` (если страница покажется тесной, это отдельное решение для всего сайта, не этого PR).

## Что отличается от Figma
В старых макетах Figma сайдбар длинный (много пунктов, группы, блок пользователя) и контент это аккордеоны. Здесь пунктов четыре, группы заложены только в данные, контент карточками. Если после живой проверки раскладка покажется тесной, сначала меняем плотность (отступы, ширина сайдбара), потом пересматриваем вариант.
