# Карточка объявления в каталоге: организация, состояние, дата

- **Маршрут:** `/catalog/[categoryId]` (уже есть). Новых страниц и маршрутов нет, меняется только карточка (`ListingCardView`, `ListingCard`, скелетон).
- **Макет:** отдельного нет. Расположение ниже выбрано по общей иерархии карточки (`docs/pages/catalog.md`, раздел «Карточка объявления»). Размеры подгоняй под сетку 8pt и токены.
- **Контекст:** прочитай `docs/pages/catalog.md` (раздел «Карточка объявления», превью карточки в форме объявления `docs/pages/listing-create.md`) и `docs/STATUS.md`.
- **Бэкенд:** PR #242 (`feature/catalog-card-data`) уже в `development` и на staging. В ответ карточки добавлены три поля, список теперь идёт новыми сверху.

## Что входит в задачу
1. Тег состояния на фото.
2. Строка с организацией-продавцом.
3. Дата публикации рядом с городом.
4. Скелетон карточки повторяет новую раскладку.
5. Превью в форме создания объявления выглядит как раньше (новых данных у него нет).

Не входит: маркер подтверждённого продавца (поля в API нет), избранное, сортировка в интерфейсе (бэкенд всегда отдаёт новые сверху).

## Данные
Перед началом выполни `npm run gen:api`. Типы только из `schema.d.ts`, ручные копии запрещены. `ListingCardResponse` (операция `getListingsCatalog`) получила поля:

| Поле | Тип | Что это |
|---|---|---|
| `created_at` | `string` (date-time, всегда есть) | дата создания объявления |
| `organization_name` | `string \| null` | название магазина, а если его нет, юридическое название; `null`, если нет обоих |
| `condition` | `string \| null` | ключ варианта атрибута «Состояние»: `new` или `used`; `null`, если у подкатегории нет такого атрибута |

Если после `gen:api` этих полей в `ListingCardResponse` нет, **остановись** и опиши расхождение в PR: значит, бэкенд на staging ещё не обновлён. Не дописывай типы вручную.

## Раскладка карточки
`ListingCardView` получает три **необязательных** пропса: `organizationName`, `condition`, `createdAt` (по тем же правилам, что остальные: без значения блок не рисуется). `ListingCard` передаёт их из `listing.organization_name`, `listing.condition`, `listing.created_at`. Остальные пропсы и поведение не меняй.

Порядок в тексте карточки сверху вниз:
1. Название (как сейчас, одна строка с обрезкой).
2. Цена (как сейчас).
3. **Организация** (новая строка): иконка `Store` (`size-4`, `shrink-0`, `aria-hidden`) и название, `text-sm text-muted-foreground`, одна строка с обрезкой (`truncate`, `min-w-0`), полный текст в `title`. Нет названия (`null` или пустая строка): строка не рисуется.
4. **Город и дата** (одна строка): слева город с иконкой `MapPin` (как сейчас, обрезается), справа дата (`shrink-0`, `text-sm text-muted-foreground`, элемент `<time dateTime={createdAt}>`). Нет даты: рисуется только город. Расстояние между левой и правой частью 8 (`gap-2`, `justify-between`).

Вертикальные отступы внутри текстовой колонки прежние (`gap-2`). Внешний вид плитки (`grid`) и списка (`list`) одинаковый: новые строки просто добавляются в ту же колонку.

### Тег состояния
Маленький тег **поверх фото** в левом верхнем углу (`absolute top-2 left-2`), внутри блока с фото (он уже `relative`): `rounded-md px-2 py-1 text-xs font-medium`.
- `new`: подпись «Новый», фон `bg-primary`, текст `text-primary-foreground`.
- `used`: подпись «Б/У», фон `bg-card`, текст `text-foreground`.
- Любое другое значение (в том числе `null`, пустая строка, неизвестный ключ): тега нет.

Подписи берутся из словаря ключей в коде (`new`, `used`): подписи с бэкенда для карточки не приходят. Проверяй ключ через `Object.hasOwn`, а не `in` (чтобы `__proto__` и подобное не дали подпись). Если у объявления нет фото (заглушка `ImageOff`), тег всё равно рисуется поверх серого блока.

### Дата
Формат: `17 нояб.` (`Intl.DateTimeFormat("ru-RU", { day: "numeric", month: "short" })`). Если год даты не совпадает с текущим, добавь год: `2 мар. 2025 г.`. Часовой пояс задан **явно**: `Asia/Almaty` (и для года тоже), иначе сервер (UTC) и браузер покажут разные даты. Слов «сегодня» и «вчера» **не используй**: страница каталога кэшируется, и такие подписи устаревают. Некорректная или пустая дата: ничего не показывать.

Хелперы (`getConditionLabel`, `formatListingDate`) вынеси в `src/components/catalog/listing-card-format.ts` и проверь вручную на нескольких значениях (граница суток в Алматы, другой год, пустое значение, неизвестный ключ). Тексты тегов и словарь лежат в этом же файле.

## Скелетон
`ListingCardSkeleton` повторяет раскладку: после полоски цены добавь одну полоску организации (`h-5 w-1/2`), ниже прежняя полоска города (`h-5 w-1/3`). Высота карточки при замене скелетона на карточку не должна прыгать.

## Превью в форме объявления
`ListingPreview` и `ListingPreviewData` **не меняй**: новые пропсы необязательные, и без них карточка рисуется как раньше. Организацию, состояние и дату в превью пока не показываем.

## Состояния и доступность
- Длинное название организации обрезается в одну строку, полный текст в `title`.
- Тег читается экранным диктором как обычный текст (`span`), отдельной роли не нужно. Контраст: `primary-foreground` на `primary` и `foreground` на `card` из токенов, hex в компонентах не писать.
- Цвета только из токенов `globals.css`, размеры по сетке 8pt (`p-1`, `p-2`, `gap-2`, `top-2`, `left-2`). Мобильный вид: плитка в одну колонку, строки обрезаются, ничего не переносится.
