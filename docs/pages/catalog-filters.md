# Каталог: фильтры, сортировка и поиск (этап 2)

- **Маршрут:** `/catalog/[categoryId]` (существующий, `docs/pages/catalog.md`), новые параметры URL ниже. Позже `/search?q=` для поиска из шапки (PR 3).
- **Доступ:** все, без авторизации.
- **Макет:** Figma «AGROW», каталог (фильтры слева 308 px, чипы выбранных фильтров над списком, сортировка в заголовке списка). Визуальный ориентир, размеры по сетке 8 и токенам. Стиль: белые панели без серого фона вокруг фильтров (`docs/STATUS.md`, раздел про стиль).
- **Рендер:** Server Component, всё состояние в URL (страницу можно открыть по ссылке). Клиентская часть только у формы фильтров.

## Зачем
Ради динамических фильтров строился весь проект: у каждой подкатегории свои атрибуты, и часть из них помечена `filterable`. Бэкенд готов (backend PR #243, #245, #246): `POST /listing/search` (`searchListing`) принимает фильтры и отдаёт те же карточки, что `getListingsCatalog`.

## Разбивка на PR
1. **PR 1 (`feature/catalog-filters`), этот промпт:** цена, город, сортировка, атрибуты подкатегории типов `enumerate`, `reference`, `boolean`; чипы и «Сбросить фильтры»; телефон. Числовые атрибуты не рисуем (см. «Ограничения»).
2. **PR 2:** числовые атрибуты диапазоном «от–до», после доработки бэкенда.
3. **PR 3:** поиск в шапке, страница `/search?q=`.

## Данные (операции API)
| Что | operationId | Где | Примечание |
|---|---|---|---|
| Дерево категорий | `getCategoryTree` | сервер | уже есть |
| Фильтры подкатегории | `getSubcategoryFilters` | сервер | `GET /catalog/{subcategory_id}/filters`, `{ filters: AttributeFieldResponse[] }`; кэш `next: { revalidate }` как у справочников. Только при выбранной подкатегории |
| Города | `getAllCities` | сервер | уже есть в `lib/api/reference.ts` |
| Бренды и др. справочники для `reference` | `getAllBrands`, `getAllColors`, `getAllOriginCountries` | сервер | по `field.source`, как в форме объявления |
| Список без фильтров | `getListingsCatalog` | сервер | как сейчас |
| Список с фильтрами | `searchListing` | сервер | `POST /listing/search`, тело `ListingSearchQuery`, ответ `PaginatedResponse[ListingCardResponse]`. Кэшировать нельзя (POST, `cache: "no-store"`) |

Перед работой: `npm run gen:api` (у `searchListing` новый ответ и поля запроса). Функцию назвать `searchListing` и положить в `lib/api/listing.ts`.

**Тело `ListingSearchQuery`:** `text`, `category_id`, `subcategory_id`, `city_id`, `price_min`, `price_max` (≥ 0), `attributes` (ключ → значение, только равенство), `sort` (`newest` | `price_asc` | `price_desc`), `page` (≥ 1), `limit` (1–50). Каталог всегда передаёт `category_id`.

**Когда какой запрос.** Нет ни одного фильтра, сортировки и текста → `getListingsCatalog` (как сейчас, из Postgres). Есть хотя бы одно → `searchListing`. Подкатегория без других фильтров фильтром не считается.

## Параметры URL
Существующие: `subcategory`, `page`, `view`. Новые:
- `price_min`, `price_max`: целые ≥ 0; если `min > max`, поменять местами при разборе.
- `city`: uuid города.
- `sort`: `newest` | `price_asc` | `price_desc`; по умолчанию не пишем.
- `f.<ключ>`: значение атрибута, например `f.condition=used`, `f.brand=<id>`, `f.<булевый>=true`.

Правила разбора (`parseCatalogParams`, `buildCatalogHref` в `components/catalog/search-params.ts` расширить):
- Некорректное значение отбрасывается молча, страница не падает.
- `f.*` учитываются только при выбранной подкатегории и только для ключей из `getSubcategoryFilters` этой подкатегории (иначе бэкенд ответит 422). Значение `enumerate` должно быть среди `options[].key`, `boolean` только `true` (галочка снята = параметра нет).
- Смена подкатегории сбрасывает `f.*` (у другой подкатегории другие атрибуты), цена, город и сортировка сохраняются.
- Любая смена фильтра или сортировки сбрасывает `page` на 1.

## Структура экрана
Сайдбар (лево, 304 как сейчас):
1. Подкатегории (`SubcategoryNav`, без изменений).
2. Панель «Фильтры» под ней:
   - **Цена, ₸:** два поля «от» и «до» в строку (`inputMode="numeric"`).
   - **Город:** селект, первый пункт «Все города».
   - **Атрибуты подкатегории** (только если подкатегория выбрана и у неё есть фильтруемые атрибуты), подпись поля = `label`, порядок как в ответе:
     - `enumerate`: селект, пункты из `options` (`label`), первый «Любое».
     - `reference`: селект по справочнику `field.source` (как в форме объявления), первый «Любой».
     - `boolean`: чекбокс с подписью `label`.
     - `integer`, `float`, `string`: не рисовать в PR 1.
   - Без выбранной подкатегории блоков атрибутов нет (без подписи и пустого места).
   - Кнопки: «Показать» (основная, применяет форму, пишет URL через `router.push`) и «Сбросить» (`ghost`, убирает цену, город, `f.*`, сортировку; подкатегория и вид остаются).
   - Применение по кнопке, а не на каждое изменение: каждое применение это запрос на сервер и скелетон списка.

Заголовок списка (`CatalogListHeader`):
- Слева «Найдено объявлений: N» (как сейчас).
- Справа селект сортировки («Сначала новые», «Сначала дешевле», «Сначала дороже»; без значения «Сначала новые») и `ViewToggle`. Смена сортировки сразу пишет URL.

Над списком, если есть хотя бы один фильтр: **чипы** выбранных фильтров («Цена: от 1 000 000 до 5 000 000 ₸», «Астана», «Состояние: Б/У», «Марка: John Deere»), у каждого крестик (убирает этот фильтр), в конце ссылка «Сбросить фильтры». Подкатегория чипом не показывается (она выбрана в сайдбаре).

Телефон (ниже `lg`): панель фильтров прячется, над списком кнопка «Фильтры» (с числом выбранных, например «Фильтры · 3»), открывает `Dialog` во весь экран с той же формой; «Показать» применяет и закрывает. Подкатегории остаются как сейчас.

## Состояния
- Загрузка списка: скелетон, как сейчас (`Suspense` с `key` по URL, ключ должен учитывать новые параметры: `buildCatalogHref` их пишет).
- Пусто с фильтрами: «По выбранным фильтрам ничего не нашлось» и кнопка «Сбросить фильтры». Пусто без фильтров: как сейчас.
- Ошибка `getSubcategoryFilters`: атрибуты не показываются, цена и город работают; остальное не ломать.
- 422 от `searchListing` (не должно случаться при правильном разборе URL): показать пустое состояние с фильтрами, не `error.tsx`. Ошибки 5xx: `error.tsx`, как сейчас.
- `page` больше числа страниц: `notFound()`, как сейчас.

## Ограничения и заметки
- **Числовые атрибуты** (`year_of_issue`, `engine_power`) бэкенд фильтрует только равенством, а нужен диапазон. Поэтому в PR 1 их нет; диапазон придёт в PR 2 вместе с полем бэкенда.
- **Значение `reference`** отправлять того же типа, что отправляет форма объявления (id из справочника), иначе равенство в Meilisearch не совпадёт.
- **Индекс поиска на staging** должен быть пересобран (`python -m scripts.reindex`), иначе поиск с `category_id` вернёт пусто. Если при проверке фильтры дают ноль, а без фильтров объявления есть, сначала проверить это.
- `total` в ответе поиска может быть чуть больше числа карточек (объявление стало неактивным после индексации), это нормально.
- Canonical каталога остаётся `/catalog/<id>` (фильтры считаются копиями).
- Тексты интерфейса на русском, цвета только токенами, сетка 8.
