# Каталог (список объявлений)

- **Маршрут:** `/catalog/[categoryId]?subcategory=<uuid>&page=<n>`. Слагов нет, везде uuid. Страница всегда открывается для **категории**; подкатегория — необязательный параметр (из мега-меню можно сразу прийти с `subcategory`).
- **Доступ:** все, без авторизации.
- **Макет:** Figma «AGROW», страница 1. Фреймы `672:206` (плитка), `672:2` (список). Это **визуальный ориентир**, а не источник размеров: числа в макете не по сетке 8pt, подгоняй под токены проекта.
- **Рендер:** Server Component. Состояние (категория, подкатегория, страница, вид) живёт в URL, чтобы страницу можно было открыть по ссылке.

## Объём работ

### Этап 1 (делаем сейчас)
- Хлебные крошки, заголовок категории.
- Сайдбар: список подкатегорий выбранной категории. **Выбор одной подкатегории, без чекбоксов**: каждая подкатегория — ссылка, клик меняет `?subcategory=` и сбрасывает страницу на 1. Пункт «Все» убирает параметр. Активная подкатегория выделена.
- «Найдено объявлений: N» (из `total`).
- Карточки: плитка (по умолчанию) и список. Переключатель вида хранится в URL (`view=grid|list`).
- Пагинация по `page` и `pages`.
- Состояния: загрузка, пусто, ошибка, 404.

### Этап 2 (после доработок бэкенда, см. ниже)
Фильтры цены, города, атрибутов (`getSubcategoryFilters`), чипы активных фильтров, «Сбросить фильтры», сортировка, текстовый поиск. На этапе 1 в интерфейсе их **нет**: не рисуй неработающие элементы.

### Вне этого экрана
Мега-меню в шапке, карточки рубрик на главной, страница объявления, избранное. Каждое — отдельная спецификация.

## Структура экрана (десктоп 1440)
1. Шапка (общий компонент в `layout`).
2. Хлебные крошки: Главная / Каталог / Рубрика / Категория.
3. Заголовок: название категории.
4. Две колонки в `Container`: сайдбар (~308px) и контент.
5. Фон страницы светло-серый, блоки белые с крупным скруглением.

## Карточка объявления
- **Плитка (3 колонки):** фото, название, цена, город (имя продавца убрано: `display_owner_name` исчезло из ответа).
- **Список:** фото слева, справа название, цена, город.
- **Цена:** число и валюта (`44 000 000 ₸`). Других вариантов («Договорная», «По запросу») нет, в макете они лишние.
- Бейджи («Новый», «Аренда» и т. п.), дата, сердечко «в избранное» в API нет. На этапе 1 не показывай.
- Клик по карточке ведёт на `/listing/<id>` (страница объявления — отдельная спецификация; пока ссылка может вести на заглушку).

## Данные (операции API)
| Что | operationId | Примечание |
|---|---|---|
| Дерево категорий (подкатегории, крошки) | `getCategoryTree` | сервер, `next: { revalidate }` |
| Список объявлений | `getListingsCatalog` | `category_id` обязателен, `subcategory_id` необязателен, `page`, `limit` |

`ListingCardResponse`: `id`, `subcategory`, `title`, `price`, `currency`, `city`, `preview_image` (uuid медиа).

**Картинки.** Preview — первое изображение объявления (позиция 0), его uuid приходит в `preview_image`. Как превратить uuid в URL, пока уточняется: заведи одну функцию `getMediaUrl(mediaId)` в `lib/api`, пока она возвращает `${NEXT_PUBLIC_API_URL}/api/v1/media/${id}`. Всё обращение к картинкам только через неё.

## Состояния
- Загрузка: `loading.tsx` со скелетонами карточек.
- Пусто: «В этой категории пока нет объявлений».
- Ошибка API: `error.tsx` с повтором.
- Невалидная категория: `notFound()`.

## Что нужно доработать на бэкенде для этапа 2
Не блокирует этап 1, но без этого фильтры не сделать.
1. **`category_id` в поиске.** В `ListingSearchQuery` есть `subcategory_id`, но нет `category_id`: нельзя искать с ценой или городом по всей категории. Добавить поле и в фильтруемые атрибуты индекса.
2. **Сортировка.** В индексе `price` и `created_at` уже sortable, а в DTO параметра сортировки нет.
3. **Схема ответа `searchListing`.** Сейчас `unknown`; нужен тип с пагинацией, как у `getListingsCatalog`.
4. **Безопасность построения фильтра.** Значения подставляются в строку фильтра Meilisearch. `subcategory_id` и `city_id` в DTO имеют тип `str` (должны быть `UUID`), ключи и значения `attributes` не экранируются и не проверяются по списку допустимых. Это даёт возможность инъекции в выражение фильтра (например, обойти условие `active = true`). Типизировать UUID, экранировать значения, ключи `attributes` брать только из белого списка подкатегории.
5. **Бейджи, дата публикации** в `ListingCardResponse` (если нужны в карточке).
