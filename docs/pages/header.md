# Шапка сайта (хедер)

- **Компонент:** `SiteHeader`, `src/components/layout/`. Показывается на всех страницах сайта, включая вход, регистрацию и восстановление пароля (через `SiteChrome` в layout групп `(site)` и `(auth)`). Без шапки только корневая 404.
- **Доступ:** все; правая часть верхнего ряда зависит от `getCurrentUser()`.
- **Макет:** описание владельца продукта (ниже) и Figma «AGROW», страница 1, фрейм `739:9` (ключ файла у владельца; без доступа к Figma делай по описанию). Макет это **визуальный ориентир**: размеры подгоняй под сетку 8pt и токены, цвета только токенами (`primary`, `cta`, `muted`, `border`). Имя пользователя в шапке на экране регистрации в старом макете это артефакт, не повторяй.
- **Рендер:** Server Component, который читает пользователя через `getCurrentUser()`.

## Главное ограничение
Шапка **не должна делать весь сайт динамическим**. Каталог и главная должны остаться кешируемыми (`revalidate`, как в `docs/pages/catalog.md`), иначе теряем кеш и SEO. Для этого блок пользователя читает сессию отдельно от остальной страницы (граница `Suspense` с заглушкой нужной высоты, без прыжка вёрстки) или решение через клиентский компонент. **Перед работой прочитай документацию Next 16 в `node_modules/next/dist/docs/`** (cookies в layout, Suspense, режимы рендера), выбери вариант и опиши в PR. Проверка: в выводе `npm run build` у страниц каталога и главной не должно появиться знака динамического рендера (ƒ), если до шапки его не было.

## Каркас
Одноуровневая шапка (редакция 21 ноября 2026, выбрана на временной странице подбора, вариант 15; страница подбора `/dev/logo` удалена перед слиянием PR #60). Внешний блок на всю ширину, `bg-background`, `border-b`, `relative z-50` (от шапки позиционируется поле поиска, и она выше затемнения). Внутри `Container`, `py-4`, один ряд высотой 40: шапка 73 px на всех ширинах. Ряд рисует сам `SiteHeader`: с `lg` сетка `grid-cols-[1fr_auto_1fr]`.

## Ряд
С `lg` сетка `grid-cols-[1fr_auto_1fr]`: разделы точно по центру страницы (проверено на 1024 и 1280).
- **Слева:** `SiteLogo`, шапочная версия логотипа (пути из `public/brand/sievers-logo-header-outlined.svg` инлайном, `currentColor`, цвет `foreground`), высота 24 (`h-6`, ≈166 px) на всех ширинах, ссылка на `/` с `aria-label="Sievers"`.
- **По центру (с `lg`, `HeaderNav`):** текстовые пункты без заливки и рамки (`HEADER_NAV_ITEM_CLASS`), по порядку: «Каталог ▾» (мега-меню, `docs/pages/mega-menu.md`), «Организации» (`/organizations`), «О нас» (`/about`), «Поддержка» (`/support`). Активный раздел (своя страница и вложенные, «Каталог» на `/catalog/…`) цветом `primary`. `/about` и `/support` пока заглушки.
- **Справа:** иконка поиска (оверлей, ниже), «Подать объявление» (`PostListingButton variant="outline"`: рамка и текст `primary`, `hover:bg-primary/5`, h-10, «+» и текст; на `lg`–`xl` только «+» с `title`, чтобы разделы остались точно по центру на 1024; ниже `md` скрыта), блок пользователя, ниже `lg` бургер.

### Блок пользователя по состояниям
| Состояние | Что показывать |
|---|---|
| Гость (`getCurrentUser()` → `null`) | круглая кнопка 40×40 с иконкой пользователя на фоне `bg-muted`, без рамки, цвет `foreground`, `hover:bg-border`, `aria-label="Войти"`, ведёт на `/login` (`GuestAccountButton`). «Регистрация» в шапке нет: она есть на странице входа |
| Пользователь (`getCurrentUser()` вернул профиль) | та же круглая кнопка 40×40 с иконкой пользователя на фоне `bg-primary/10`, цвет `primary`, `hover:bg-primary/20`, открывает меню (ниже). Без аватарок, инициалов и стрелки |

Все элементы ряда высотой 40. Заглушка загрузки: круг 40×40.

### Меню пользователя
- **Кнопка:** круг 40×40 с иконкой `UserRound` (`UserMenu`), `aria-label` «Меню пользователя», `aria-haspopup="menu"` и `aria-expanded` ставит Radix. Аватарки и буквы нет (`avatar_url` не показываем, backend#208).
- **Меню (dropdown):** открывается **по клику**, не при наведении (на телефоне наведения нет). Закрывается по Esc, клику вне, выбору пункта. Клавиатура как у настоящего меню (стрелки, Enter). Компонент `dropdown-menu` из shadcn (`npx shadcn add dropdown-menu`; Radix уже разрешён, новых пакетов добавлять не нужно). Отступы внутри 16. Сверху в меню строка с именем («Фамилия Имя», если оба заданы; иначе «Пользователь», не почта), под ней всегда почта: приглушённая (`text-muted-foreground`) и мельче имени (`text-xs`). «Выйти» отделён разделителем от пунктов выше, цвет обычный (не красный).
- Пункты добавляются, только когда страница существует (не показывай ссылки в пустоту):
| Пункт | Когда добавить |
|---|---|
| Аккаунт (`/account`, `User`) | **есть**, первым (решение владельца, 21 ноября 2026) |
| Мои организации (`/account/organizations`, `Building2`) | **есть** (PR 2, `docs/pages/organizations.md`) |
| Мои объявления (`/account/listings`, `FileText`) | **есть** (`feature/header-menu`) |
| Выйти (`LogOut`, после разделителя) | **есть** |
| Избранное | когда будет функция |

Пункты берутся из `ACCOUNT_MENU_ITEMS` (`components/account/account-nav-items.ts`): те же, что в сайдбаре кабинета, в том же порядке, без пунктов без страницы. Сейчас «Аккаунт», «Мои организации», «Мои объявления», затем разделитель и «Выйти». Новый пункт кабинета со страницей появится и в меню сам.
- **Ниже `md`:** вместо выпадающего меню панель справа (`MobileAccountSheet`) с теми же пунктами и «Выйти» (раздел «Ниже `lg`»).

- **Выход:** «Выйти» вызывает `logoutUser()`. После ответа: перенаправление на `/` и `router.refresh()`, чтобы шапка и серверные компоненты увидели гостя. Ошибку выхода (сеть, 401) не показывай как проблему: пользователь в любом случае попадает на `/` как гость. Во время запроса кнопка заблокирована.

## Поиск
Иконка поиска (40×40, без рамки) открывает поле под шапкой на всю ширину (`HeaderSearchOverlay`), страница под шапкой затемняется (`bg-foreground/40`, порталом в `body`), шапка остаётся видна, прокрутка страницы на это время заблокирована. Поле это `HeaderSearch` (то же поведение: Enter ведёт на `/search?q=`, пустой запрос не уходит, на `/search` в поле текущий `q`), в фокусе сразу. Закрытие: Esc, клик по затемнению, отправка запроса, смена маршрута; фокус возвращается на иконку. Подсказок при вводе нет.

## Ниже `lg`
Центральной части нет. Справа по порядку: иконка поиска, с `md` «Подать объявление», иконка профиля, бургер. На телефоне промежуток 8 (с `md` 16), на 375 без прокрутки (бургер у правого отступа).
- **Бургер** (`HeaderMobileMenu`, `Sheet side="left"`, на весь экран ниже `lg`: `w-full sm:max-w-none`): сверху логотип и закрытие, ниже один столбец экранов «вглубь» (`MobileCatalogDrilldown`, `docs/pages/mega-menu.md`). Первый экран: заголовок «Каталог» (`text-lg font-semibold`) и рубрики с шевроном, «Организации», «О нас», «Поддержка» (активный `primary`), внизу «Подать объявление» (`PostListingButton variant="outline" alwaysShowLabel`). Кабинета и входа в бургере нет.
- **Профиль:** ниже `md` иконка вошедшего открывает панель справа (`MobileAccountSheet`, `Sheet side="right"`): имя и почта, пункты кабинета (`ACCOUNT_MENU_ITEMS`, тот же порядок, «Аккаунт» первым), «Выйти» последним. С `md` — выпадающее меню (`UserMenu`, `min-w-56`, `collisionPadding=16`). Гость на любой ширине сразу переходит на `/login`; на самой `/login` у ссылки `aria-current="page"` (вид тот же).
