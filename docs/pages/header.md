# Шапка сайта (хедер)

- **Компонент:** `SiteHeader`, `src/components/layout/`. Показывается на всех страницах сайта (каталог, главная, служебные), кроме страниц входа и регистрации: там только логотип со ссылкой на `/`, без остального.
- **Доступ:** все; правая часть верхнего ряда зависит от `getCurrentUser()`.
- **Макет:** описание владельца продукта (ниже) и Figma «AGROW», страница 1, фрейм `739:9` (ключ файла у владельца; без доступа к Figma делай по описанию). Макет это **визуальный ориентир**: размеры подгоняй под сетку 8pt и токены, цвета только токенами (`primary`, `cta`, `muted`, `border`). Имя пользователя в шапке на экране регистрации в старом макете это артефакт, не повторяй.
- **Рендер:** Server Component, который читает пользователя через `getCurrentUser()`.

## Главное ограничение
Шапка **не должна делать весь сайт динамическим**. Каталог и главная должны остаться кешируемыми (`revalidate`, как в `docs/pages/catalog.md`), иначе теряем кеш и SEO. Для этого блок пользователя читает сессию отдельно от остальной страницы (граница `Suspense` с заглушкой нужной высоты, без прыжка вёрстки) или решение через клиентский компонент. **Перед работой прочитай документацию Next 16 в `node_modules/next/dist/docs/`** (cookies в layout, Suspense, режимы рендера), выбери вариант и опиши в PR. Проверка: в выводе `npm run build` у страниц каталога и главной не должно появиться знака динамического рендера (ƒ), если до шапки его не было.

## Каркас
Внешний блок шапки на всю ширину экрана, фон белый (`bg-background`), снизу тонкая граница (`border-b`). Внутри `Container` (максимум 1280, боковые отступы 16, чтобы на телефоне содержимое не липло к краям). Высота не фиксируется: задаётся содержимым; ориентир на десктопе 128-144 px (два ряда + отступы). Расстояние между элементами по умолчанию 16.

## Верхний ряд
- **Слева:** текстовый логотип «Sievers Market» (обе буквы заглавные), ссылка на `/`, прижат к левому краю контейнера. Картинку логотипа добавим позже.
- **Справа:** разделы-заглушки, затем блок пользователя, прижат к правому краю.
  - Разделы («Поставщики», «Поддержка» или другие) пока **не добавляй**: нет страниц и нет решения по составу. Оставь место в вёрстке (слот), чтобы потом добавить без переделки.
  - Блок пользователя по состояниям (ниже).

### Блок пользователя по состояниям
| Состояние | Что показывать |
|---|---|
| Гость (`getCurrentUser()` → `null`) | две кнопки: «Войти» (контурная: рамка `primary`, текст `primary`, фон прозрачный) слева и «Регистрация» (залитая `primary`, белый текст) справа, правее всех |
| Пользователь (`getCurrentUser()` вернул профиль) | кнопка-аватар с меню (ниже), на месте кнопок гостя |

Высота кнопок 40 или 48, внутренние отступы по горизонтали 24, скругление как у остальных кнопок проекта. Все кнопки одной высоты в ряду.

### Аватар и меню
- **Кнопка:** круг с буквой на сером фоне (`muted`), опционально маленькая стрелка вниз. Буква: `first_name[0]`, если имя есть, иначе первая буква почты (ФИО может быть `null`, регистрация имя не спрашивает). `avatar_url` пока не показывай (картинки не работают из-за хранилища, backend#208). У кнопки `aria-label` («Меню пользователя»).
- **Меню (dropdown):** открывается **по клику**, не при наведении (на телефоне наведения нет). Закрывается по Esc, клику вне, выбору пункта. Клавиатура как у настоящего меню (стрелки, Enter). Компонент `dropdown-menu` из shadcn (`npx shadcn add dropdown-menu`; Radix уже разрешён, новых пакетов добавлять не нужно). Отступы внутри 16. Сверху в меню строка с именем («Фамилия Имя», если оба заданы; иначе только почта) и почта серым.
- Пункты добавляются, только когда страница существует (не показывай ссылки в пустоту):
| Пункт | Когда добавить |
|---|---|
| Выйти | **сейчас** |
| Мои организации (`/account/organizations`) | в PR 2, с экраном `docs/pages/organizations.md` |
| Мои объявления | с экраном «Мои объявления» |
| Избранное | когда будет функция |

- **Выход:** «Выйти» вызывает `logoutUser()`. После ответа: перенаправление на `/` и `router.refresh()`, чтобы шапка и серверные компоненты увидели гостя. Ошибку выхода (сеть, 401) не показывай как проблему: пользователь в любом случае попадает на `/` как гость. Во время запроса кнопка заблокирована.

## Нижний ряд
Один ряд из трёх элементов, расстояние 16. Высота 48 (кнопки и поле одной высоты).
- **Слева кнопка «Каталог»:** залитая `primary`, белый текст и иконка слева (сетка из квадратов, например `lucide-react` `LayoutGrid`; иконки берём из уже установленного `lucide-react`). Открывает мега-меню каталога (`CatalogMegaMenu`, `docs/pages/mega-menu.md`): с `lg` панель под шапкой, ниже `lg` окно во весь экран. Сама кнопка никуда не ведёт: `/catalog` без id нет.
- **По центру поле поиска на всю оставшуюся ширину:** серый фон (`muted`), слева иконка лупы, placeholder «Поиск по объявлениям». Пока **без функции** (по `listing/search` отдельная спецификация, нужны backend#205, #206): поле неактивно (`disabled`) или без отправки, решай сам и опиши в PR.
- **Справа кнопка «Подать объявление»:** залитая `cta` (синий), текст `cta-foreground`. Куда ведёт, зависит от пользователя шапки (см. `docs/pages/polish.md`, п. 8).

## Мобильная версия (предложение, mobile-first)
- Верхний ряд: логотип слева, справа аватар (или «Войти» без «Регистрация», регистрация на странице входа есть). Регистрация и «Подать объявление» на телефоне не помещаются.
- Нижний ряд: кнопка «Каталог» только иконкой (с `aria-label`) слева, поле поиска на оставшуюся ширину.
- «Подать объявление» на телефоне скрыто, пока нет нижней навигации; опиши в PR, как поступил.
- Меню аватара не выходит за экран.

## Состояния
Загрузка блока пользователя: заглушка (круг или две серые полосы той же высоты, без прыжка вёрстки). Ошибка `getCurrentUser()` (не 401): считать гостем и не ломать страницу; не показывать ошибку в шапке.

Функция поиска (мега-меню «Каталога» сделано отдельно, `docs/pages/mega-menu.md`), разделы «Поставщики» и «Поддержка», избранное и уведомления, переключатель языка, картинка логотипа, `avatar_url`.

## Расхождения (не придумывать, описать в PR)
1. Если в макете есть элементы, которых здесь нет, не добавляй их, перечисли в PR.
2. Обновления токена на сервере (`proxy.ts`) пока нет: после истечения access-cookie (30 минут) шапка показывает гостя, пока пользователь не войдёт снова. Это известное ограничение, не чини.
3. Поведение «Подать объявление» для покупателя (у него нет права создавать объявления) решим с экраном создания.
