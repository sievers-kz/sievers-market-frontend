# Создание объявления

- **Маршрут:** `/listings/new`, заменяет заглушку в `src/app/(site)/listings/new/`. Нужны `page.tsx`, `loading.tsx`, `error.tsx`. Кнопка «Подать объявление» в шапке уже ведёт сюда.
- **Макет:** Figma «AGROW», экран «Новое объявление» (три состояния: пустая форма, форма с загруженными фото, скелетон после выбора подкатегории). Макет это **визуальный ориентир**: размеры подгоняй под сетку 8pt и токены; шапку и навигацию из макета не повторяй, на странице обычный `SiteHeader`.
- **Референс по поведению:** старый фронтенд (репозиторий `sievers-market-frontend-legacy`, ветка `development`): `src/widgets/listing-creation/`, `src/features/create-listing/`, `src/features/get-subcategory-form/`, `src/features/upload-media/`. Читай как пример логики (каскад селектов, динамические поля, загрузка), код не копируй: там FSD, `apiRequest` и другие компоненты.
- **Доступ:** любой авторизованный пользователь с **подтверждённой организацией** (`registry_status: verified`). Проверяй в браузере, в клиентском компоненте (на сервере токен не обновляется, при истёкшем access-токене серверная проверка ошибочно отправила бы вошедшего на `/login`). Пока идёт проверка, скелетон. Нет входа → `/login?next=/listings/new`. Нет организаций или ни одна не `verified` → вместо формы заглушка (тексты и ветки в `docs/pages/organizations-migration.md`, раздел «PR 3»). Форма показывается, только когда есть хотя бы одна `verified`. Контекст миграции на организации — там же.

## Данные (операции API)
| Что | operationId | Примечание |
|---|---|---|
| Дерево рубрика → категория → подкатегория | `getCategoryTree` | сервер, `next: { revalidate }`; передай в клиентскую форму пропсом |
| Поля формы подкатегории | `getSubcategoryForm` | клиент, после выбора подкатегории |
| Города | `getAllCities` | список без пагинации |
| Бренды, цвета, страны | `getAllBrands`, `getAllColors`, `getAllOriginCountries` | для полей с `type: "reference"`, имя источника в `field.source` (`brand`, `color`, `country`) |
| Ссылка на загрузку | `generateUploadUrl` | `files: [{client_filename, mime_type}]`; можно сразу все файлы |
| Загрузка файла | `uploadToPresignedUrl` из `lib/api/upload.ts` | `PUT` в MinIO, без cookie |
| Подтверждение | `confirmUpload` | `files: [{file_path, media_type, media_size}]` → `media_id` |
| Организации пользователя | `getOrganizations` | клиент; для выбора берём только `registry_status === "verified"` |
| Создание | `createListing` | см. ниже |

Справочники (города, бренды, цвета, страны) читай на сервере с `next: { revalidate }` и передавай в форму пропсами, в Zustand не копируй. Функции запросов клади в `src/lib/api/<домен>.ts` по `operationId`.

`createListing`: `organization_id` (uuid выбранной подтверждённой организации), `category_id` (выбранная категория, не рубрика), `subcategory_id`, `title`, `price` (целое), `currency` (`KZT`, `RUB`, `USD`, `EUR`), `city_id`, `description` (строка или `null`, поле обязательное), `gallery` (`[{media_id, media_type, media_size}]`, от 1 до 10 элементов), `attributes` (словарь). В ответе `response` с uuid созданного объявления, но схема ответа в OpenAPI пустая (`unknown`): достань id узким рантайм-разбором (без `any` и без ручной копии типа ответа), и опиши расхождение в PR. После успеха редирект на `/listing/<id>`. Объявление публикуется сразу (статус `active`), модерации нет.

## Раскладка
Контент внутри `Container`, фон светло-серый, блоки белые со скруглением, как на других экранах.

1. **Заголовок** `h1` «Новое объявление» (обычный текст, без цвета).
2. **Организация** (компонент `OrganizationSelect`, см. ниже): отдельный блок на всю ширину над выбором каталога.
3. **Выбор каталога:** три равных поля в ряд, зазор 16: «Рубрика», «Категория», «Подкатегория». Каскад: пока не выбрана рубрика, категория недоступна; смена верхнего уровня сбрасывает нижние и форму. С телефона столбиком.
4. **Основной блок:** две колонки с `lg`: слева форма (аккордеоны), справа ширина около 320 px подсказки; на телефоне одна колонка, подсказки под формой.
5. **Кнопка «Опубликовать»** внизу левой колонки, `cta`, на всю ширину колонки, высота 48.

## Организация (`OrganizationSelect`)
Дизайн выбора организации не утверждён (Figma «Frame 848» — ориентир). Делай изолированным компонентом `src/components/listing-create/organization-select.tsx` (shadcn `Select`), чтобы его можно было перенести или заменить карточками без правок остальной формы.
- Опции: только организации со `registry_status === "verified"`. Подпись опции: `shop_name`, иначе `legal_name`; второй строкой номер (`tax_id`) и тип (ИП / Юридическое лицо).
- Если подтверждённая организация одна, она выбрана сразу (это удобство, а не «организация по умолчанию»: бэкенд основной организации не знает). Если их несколько, ничего не выбрано, поле обязательное (`organization_id`, `uuid` в Zod, сообщение «Выберите организацию»).
- Если у пользователя есть неподтверждённые организации (`pending` / `not_found`), под полем серым текстом: «Некоторые организации ещё не подтверждены и недоступны для выбора» со ссылкой «Мои организации» (`/account/organizations`).
- Выбор организации не сбрасывается при смене подкатегории и не влияет на динамические поля.

## Форма
Пока подкатегория не выбрана, под выбором каталога пустое состояние: «Выберите подкатегорию, чтобы заполнить объявление». После выбора запрашивается `getSubcategoryForm`; пока идёт запрос, скелетоны аккордеонов (`Skeleton`, как в третьем макете), при ошибке сообщение и кнопка «Повторить».

**Аккордеоны** (shadcn `accordion` через `npx shadcn add accordion`, тип `multiple`, по умолчанию все раскрыты; высота заголовка 72 в макете, подгони по сетке, около 64–72). Порядок сверху вниз:
1. «Параметры объявления» (статический): заголовок (`title`, строка), цена (`price`, целое, больше 0), валюта (по умолчанию `KZT`), город (`city_id`).
2. Группы из формы подкатегории в порядке `position`, заголовок `group.label`, внутри поля группы.
3. «Изображения».
4. «Описание» (`description`, многострочное, необязательное).

**Поля динамических групп** по `field.type`:
- `string` — `Input`;
- `integer`, `float` — числовое поле (целое: шаг 1; значение отправляй числом, не строкой), единица измерения из `field.unit` справа, если есть;
- `boolean` — переключатель (`Checkbox`);
- `enumerate` — выбор из `field.options` (`option.key` значение, `option.label` подпись);
- `reference` — выбор из справочника по `field.source` (значение — `id`).
- Подпись `field.label`, звёздочка у `required`. Все поля одной колонкой на всю ширину аккордеона (по два в ряд не группируем).
- В OpenAPI `options` и `unit` типизированы как произвольные словари: читай их узким рантайм-разбором, без `any`; расхождения запиши в PR (мы это заведём в Issue бэкенда).
- Необязательные пустые поля в `attributes` не отправляй (ключ отсутствует), а не `null`.

**Изображения.** Белая область с пунктирной рамкой: «Добавить фото / Загрузите или перетащите сюда», клик открывает выбор файлов, работает перетаскивание. Допустимы `image/png`, `image/jpeg`, `image/webp`; **до 5 МБ каждое**, не больше 10 штук; на лишнее и на большой файл показывай понятное сообщение (клиентская проверка, бэкенд отклонит такое иначе). Загрузка начинается сразу при выборе: `generateUploadUrl` → `uploadToPresignedUrl` → `confirmUpload`, по каждому файлу индикатор, при ошибке «Ошибка» с кнопкой повторить или убрать. Превью локальные (`URL.createObjectURL`, не забывай `revokeObjectURL`), в `gallery` попадают только файлы, у которых `confirmUpload` вернул `media_id`. Первое фото обложка (подпись «Обложка»). Каждое фото можно убрать; перестановку не делаем. Пока идёт загрузка, кнопка «Опубликовать» недоступна.

## Проверка и ошибки
- Ошибки создания по организации: 404 `organization_not_found_error` и 403 `organization_cannot_publish_error` (организацию удалили или она потеряла подтверждение) показывай сообщением формы над кнопкой «Опубликовать» и перезагрузи список организаций (`getOrganizations`).
- Схему формы собирай в Zod по DTO `CreateListingRequest` (обязательность и ограничения как в OpenAPI) плюс динамические поля из `getSubcategoryForm` (число/строка/выбор, `required`). Форма на `react-hook-form`, схема строится заново при смене подкатегории.
- Сообщение об ошибке на поле, аккордеон с ошибкой раскрывается и подсвечивается, прокрутка к первой ошибке.
- Ошибки бэкенда (`ApiError`): коды и 422 раскладывай по полям через `applyApiErrorToForm`. Ошибки значений `attributes` бэкенд пока присылает сырыми от Pydantic (на английском, с `loc` вида `attributes.<ключ>`): показывай как есть под полем, если ключ определяется, иначе сообщением формы. Ошибки без поля показывай сообщением формы над кнопкой.
- Если пользователь ушёл со страницы с несохранёнными данными, не перехватываем (черновиков нет).

## Проверить в первую очередь
1. **CORS при загрузке из браузера.** До сих пор `PUT` в MinIO проверяли только через `curl`. Первым шагом сделай рабочую загрузку одного файла (выбор файла → ссылка → `PUT` → `confirmUpload`) и убедись, что браузер не блокирует запрос. Если блокирует (ошибка CORS в консоли), остановись и опиши в PR, остальное не делай: чинится на стороне nginx/MinIO.
2. Проверь поток на стенде пользователем с подтверждённой организацией, создай объявление с 2–3 фото и открой его на странице объявления.

## Что не делаем сейчас
Черновики, редактирование, перестановка фото, обрезка и поворот, автосохранение, разбивка полей по два в ряд, проверка уникальности названия. Подписи и значения характеристик на странице объявления пока сырые (backend#217): форма создания знает подписи из `getSubcategoryForm`, но страница объявления ещё нет.

## Бэкенд (замечено, не блокирует)
- `createListing` не имеет схемы ответа в OpenAPI (`unknown`); в `AttributeFieldResponse` `options` и `unit` описаны как произвольные словари.
- Ошибки валидации атрибутов приходят сырыми (без `error_code` и без перевода).
- У объявления нет операции для изменения галереи (backend#219).
- `createListing` не проверяет, что `media_id` из `gallery` существуют (backend#220 о близкой проблеме).
