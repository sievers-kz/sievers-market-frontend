# Блок организации в форме объявления

- **Экран:** `/listings/new`, блок «Организация» (левая колонка, над выбором каталога). Остальная форма не меняется.
- **Зачем.** Сейчас выбор организации знает только `registry_status`, а бэкенд для публикации требует ещё название магазина, телефон и email организации. Пользователь выбирает «доступную» организацию, заполняет всю форму и только после отправки получает 403 `organization_profile_incomplete_error`. Задача: форма показывает состояние организации **сразу после выбора**, а не после отправки. Контакты принадлежат организации: в форме объявления они **только показываются**, редактируются на странице организации.
- **Контекст:** `docs/pages/listing-create.md` (форма целиком), `docs/pages/organization-detail.md` (где данные заполняются), `docs/pages/organizations-migration.md` (почему организации). Дизайн блока **не утверждён**: сделай первый заход по описанию ниже, отличия от него и от других экранов отметь в PR.
- **Бэкенд не меняется.** `getOrganizations` (список) `missing_fields` не отдаёт, и это не нужно: подробности запрашиваются только для выбранной организации.

## Что входит в задачу
1. Новый блок с данными выбранной организации (только чтение), состояния загрузки и ошибки.
2. Ошибка «не хватает данных» показывается **в этом блоке**: до отправки (по `missing_fields`) и после 403.
3. Удаляется прежняя обработка `organization_profile_incomplete_error` отдельным сообщением формы со ссылкой (она стоит между описанием и кнопкой «Опубликовать» и выглядит не на месте).

## Данные (операции API)
| Что | operationId | Примечание |
|---|---|---|
| Организации пользователя | `getOrganizations` | уже есть; для выбора по-прежнему только `registry_status === "verified"` |
| Данные выбранной организации | `getOrganization` | уже есть в `src/lib/api/organization.ts`; клиент, `cache: "no-store"` |

Из `OrganizationResponse` нужны: `id`, `shop_name`, `contact_phone`, `contact_email`, `missing_fields`. Типы только из `schema.d.ts`.

**`missing_fields` это единственный источник правила «чего не хватает».** Бэкенд считает его сам (названия полей: `shop_name`, `contact_phone`, `contact_email`). На фронте не проверяй значения на `null` и пустую строку, чтобы решить, заполнена организация или нет: смотри только в `missing_fields`. Значения (`shop_name` и т. д.) нужны только чтобы их показать.

## Поведение
Загрузка данных живёт в `ListingCreateFlow` (там уже хранится выбранная `organizationId`), вынеси её в хук `useOrganizationDetails(organizationId)` рядом с компонентами формы. Он возвращает состояние `idle | loading | ready | error` и `reload()`.

- **Организация не выбрана** (`organizationId === ""`): `idle`, блок данных не показывается, остаётся только выбор.
- **Выбрали или сменили организацию:** запрос `getOrganization(id, { signal })`. Прошлый запрос отменяй (`AbortController`), устаревший ответ игнорируй. Пока идёт запрос, в блоке скелетон тех же трёх строк (высота не прыгает).
- **`ready`:** показываем блок данных (ниже). Выбор организации и вся форма остаются доступными.
- **Ошибка запроса** (сеть, 5xx): в блоке сообщение «Не удалось загрузить данные организации» и кнопка «Повторить». Форма **не блокируется**: если данные не загрузились, отправку не запрещаем, правило проверит бэкенд (403 обработается как ниже).
- **404 `organization_not_found_error`** (организацию удалили после открытия страницы): вызови уже существующий `onOrganizationsStale()` (список перечитывается, выбор сбрасывается обычной логикой), отдельного сообщения не нужно.
- **Возврат со страницы организации.** Пользователь по ссылке открывает организацию в новой вкладке, заполняет данные и возвращается. Пока у выбранной организации непустой `missing_fields`, перечитывай данные при возврате на вкладку (`visibilitychange` в `visible`, при `document.visibilityState === "visible"`; без таймеров и опроса). Перечитывание тихое: блок не заменяется скелетоном, старое значение остаётся до прихода нового. Если `missing_fields` пуст, повторных запросов нет.

## Блок данных (`OrganizationSummary`)
Файл `src/components/listing-create/organization-summary.tsx`, один компонент на файл. Лежит **внутри той же карточки «Организация»**, под выбором (`OrganizationSelect` остаётся как есть и принимает его как `children` или рисуется рядом внутри общего контейнера; карточку-обёртку при необходимости перенеси из `OrganizationSelect` во `Flow`, чтобы выбор и блок были одной карточкой `rounded-2xl bg-card p-6`).

Первый заход по дизайну: внутри карточки под селектом вставка `rounded-xl bg-muted p-4`, отступ от селекта 16. Содержимое сверху вниз:
1. **Шапка вставки:** слева «Покупатель увидит» (`text-sm text-muted-foreground`), справа ссылка (см. ниже).
2. **Три строки** (`dl`, подпись слева, значение справа, на телефоне столбиком): «Название магазина», «Контактный телефон», «Контактный email». Подписи с красной звёздочкой (`text-destructive`, `aria-hidden`), как на странице организации. Значение `text-base`, длинное переносится (`break-words`).
   - Если имя поля есть в `missing_fields`, вместо значения «Не указано» (`text-muted-foreground`, одна формулировка везде).
   - Иначе значение из ответа.
3. **Подсказка** (только если `missing_fields` непустой): строка `text-sm` под тремя строками: «Заполните данные магазина, чтобы подать объявление».
4. **Ссылка** на `/account/organizations/<id>`: если `missing_fields` непустой, текст «Заполнить в организации», иначе «Изменить в организации». Открывается **в новой вкладке** (`target="_blank"`, `rel="noopener noreferrer"`), потому что иначе введённая форма и загруженные фото пропадут. Для скринридера добавь `sr-only` текст «(откроется в новой вкладке)». Цвет `primary`, подчёркивание при наведении, высота нажимаемой области не меньше 40.

### Состояние ошибки (красная рамка)
Блок получает проп `error?: string`. Когда он задан:
- вставка получает рамку `border border-destructive` (токен, не hex);
- подсказка из пункта 3 становится красной (`text-destructive`), текст берётся из `error` (он же говорит, что делать);
- у блока `role="alert"`; `aria-invalid` ставится на триггер селекта (он уже получает `aria-invalid` по `error`).

Когда ошибка есть:
- пользователь нажал «Опубликовать», а у выбранной организации непустой `missing_fields`. **Запрос не отправляется.** Ошибка ставится тем же путём, что и ошибка поля `organization_id` (он уже стоит первым в порядке прокрутки и фокуса): форма прокручивается к блоку и фокус идёт на селект организации. Если при этом невалидны и другие поля, ошибка организации показывается вместе с остальными, фокус на первой по порядку (организация выше всех);
- бэкенд ответил 403 `organization_profile_incomplete_error` (данные успели устареть или не загрузились): та же ошибка на блоке, и дополнительно вызови `reload()` данных организации, чтобы блок показал актуальные `missing_fields`.

Ошибка сбрасывается, как только в данных организации `missing_fields` пуст (после возврата на вкладку и перечитывания) или пользователь выбрал другую организацию.

Текст ошибки один: «Заполните данные магазина, чтобы подать объявление» (константа рядом с компонентом, как остальные тексты формы).

## Что убрать из текущего кода
- В `listing-form.tsx`: `PROFILE_INCOMPLETE_TEXT`, состояние `incompleteOrganizationId`, ветку `errors.root?.type === ERROR_CODES.organizationProfileIncomplete` с `Link` и `import Link`, если он больше нигде не нужен. Код `organizationProfileIncomplete` в `ERROR_CODES` остаётся: по нему ловится 403.
- Обработка 403 `organization_profile_incomplete_error` превращается в «поставить ошибку блока организации и перечитать данные» (см. выше). Она больше не пишет в `errors.root`.
- Остальные ошибки организации (404 `organization_not_found_error`, 403 `organization_cannot_publish_error`) **не меняй**: они по-прежнему сообщением формы над кнопкой и `onOrganizationsStale()`.

## Выбор организации не меняется
Организации с неполными данными **остаются доступными для выбора**: блок как раз показывает, чего им не хватает. Не прячь и не отключай их, не добавляй `missing_fields` в список организаций, не пересчитывай правило на фронте.

## Состояния
- Организация не выбрана: блока нет.
- Загрузка: скелетон трёх строк внутри вставки.
- Данные есть, всё заполнено: три значения и ссылка «Изменить в организации».
- Не хватает данных: «Не указано», подсказка, ссылка «Заполнить в организации»; после попытки отправки красная рамка.
- Ошибка загрузки: сообщение и «Повторить».

## Что не делаем
Правку данных организации прямо в форме объявления, выбор контактного лица или менеджера для объявления (задел: блок станет местом, где контакт «подкрепляется» к объявлению, но сейчас контакты одни и те же у всей организации), основную организацию, отключение организаций с неполными данными в выборе, `missing_fields` в списке организаций, кэш данных организации между выборами, проверку правила на фронте, опрос таймером.

## Проверить
`typecheck`, `lint`, `build`. Руками (подмени ответы API или возьми организацию на стенде):
1. выбор организации с полными данными: три значения, «Изменить в организации», ошибки нет;
2. выбор организации без телефона или email: «Не указано», подсказка, «Заполнить в организации»;
3. «Опубликовать» с такой организацией: запрос не уходит, красная рамка на блоке, прокрутка и фокус на селект;
4. заполнить данные в новой вкладке и вернуться: блок обновился без скелетона, ошибка пропала;
5. быстрая смена организации туда и обратно: нет мигания старыми данными;
6. ошибка загрузки: «Повторить», форму по-прежнему можно отправить;
7. форма и фото не пропали после перехода по ссылке (новая вкладка).
