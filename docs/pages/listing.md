# Страница объявления («деталка»)

- **Маршрут:** `/listing/[listingId]`, файл в `src/app/(site)/listing/[listingId]/` (`page.tsx`, `loading.tsx`, `error.tsx`, `not-found.tsx`). Карточки каталога уже ведут сюда.
- **Доступ:** все, без входа.
- **Макет:** Figma «AGROW», «деталка объявления V3», фрейм `770:472`. Это **визуальный ориентир**: структура и состав блоков. Размеры подгоняй под сетку 8pt и токены. Блоков, для которых в API нет данных, в первой версии нет (список ниже), заглушек «скоро» не рисуй.
- **Рендеринг:** страница серверная. Клиентскими делай только галерею, кнопку «Контакты» и сворачивание описания.

## Данные
| Что | operationId | Примечание |
|---|---|---|
| Объявление | `getListingDetails` | `GET /api/v1/listing/{listing_id}`, функцию добавь в `src/lib/api/listing.ts` |

`ListingDetailResponse`: `id`, `owner_id` (id организации-продавца), `subcategory` (название), `title`, `price`, `currency`, `city`, `description` (может быть `null`), `gallery` (массив uuid медиа), `attributes` (словарь произвольных значений).

- Бэкенд отдаёт только активные объявления. Любое другое (нет такого, снято, архив) приходит как 404 `ListingNotFoundError` → `notFound()`. Невалидный uuid в адресе (422) тоже → `notFound()`.
- `generateMetadata`: заголовок страницы «название объявления · Sievers Market», описание берётся из первых 160 символов `description`.

## Раскладка
Всё внутри `Container`, фон страницы и блоки как в каталоге (светло-серый фон, белые блоки с крупным скруглением).

1. **Хлебные крошки:** Главная / Каталог / название подкатегории (`subcategory`), последний пункт текст. Рубрики и категории в ответе нет (см. «Бэкенд»), поэтому только так.
2. **Карточка с названием:** белая карточка (`bg-card`, скругление и `p-6`, как у остальных блоков) на всю ширину `Container`, под хлебными крошками и над колонками.
3. **Две колонки с `lg`**, на телефоне одна колонка.
   - **Слева:** галерея, «Характеристики», «Описание».
   - **Справа** (`sticky`, ширина около 400px по сетке): карточка с ценой (карточки продавца пока нет).
4. **Порядок на телефоне:** карточка с названием → галерея → карточка с ценой → характеристики → описание.

## Блоки
**Галерея** (клиентский компонент). Крупное фото 4/3 (`object-cover`, скругление), счётчик `1 / N`, стрелки (скрыты при одном фото), под фото ряд миниатюр, клик по миниатюре меняет главное. Стрелки и миниатюры доступны с клавиатуры, у кнопок `aria-label`. Фото через `getMediaUrl(id)` и `next/image`. Пока картинки не открываются (backend#208), или массив пуст, показывай серую заглушку с `ImageOff`, как в карточке каталога. Свайп и полноэкранный просмотр не делай.

**Карточка с названием** (над колонками):
- название подкатегории маленьким текстом сверху (`subcategory`), не ссылка;
- `h1` с `title`;
- город с иконкой `MapPin`.

**Карточка с ценой:** только цена крупно через `formatPrice` из `components/catalog/format-price.ts` (вынеси в общее место, если импортировать из каталога неудобно); валюту подписывает сам `formatPrice`. Больше ничего: ни названия, ни города, ни кнопок.

**Карточка продавца: пока не выводится.** В ответе больше нет ни имени продавца (`display_owner_name`), ни телефона (`contact_phone`): данные организации-владельца в деталку не приходят (backend#207). Блок вернём отдельной задачей, когда решим, какие данные показывать; заглушек вместо него не рисуй. Компоненты `SellerCard` и `ShowPhoneButton` удаляются в PR 1.

**Характеристики:** сетка плиток 2 колонки на телефоне, 3 с `md`; в плитке подпись (muted) и значение. Берутся из `attributes`. Пропускай `null`, пустые строки и вложенные объекты. Подписи в API нет, поэтому пока подпись это ключ как есть (`engine_power`) — это временно, помечай `// TODO` и держи вывод подписи в одной функции `getAttributeLabel(key)`. Если после фильтра пусто, блока нет.

**Описание:** заголовок «Описание» и текст с сохранением переносов строк (`whitespace-pre-line`). Если длиннее 8 строк, сворачивай с кнопкой «Показать полностью» (клиентский компонент или `<details>`; выбери проще). Если `description` равен `null`, блока нет. Текст выводи как текст, не как HTML.

## Что есть в макете, но не делаем сейчас
Нет данных в API или нет самой функции:
- теги/бейджи («Новое», «Партнёр») и «Проверен по БИН» (`is_verified` лежит в профиле продавца и в деталку не приходит);
- дата публикации и просмотры;
- «Возможен торг»;
- «Написать продавцу», «В избранное», «Поделиться» (нет ни чатов, ни избранного);
- «Компания · N объявлений» и «Все объявления продавца»;
- блок «Местоположение» с картой (есть только название города);
- «Другие объявления продавца»;
- плашка «Безопасная сделка» (обещает функцию, которой нет);
- логотип продавца (бэкенд читает его из БД, но не отдаёт).

В описании PR перечисли это как отличия от макета.

## Состояния
- Загрузка: `loading.tsx`, скелетон двух колонок (серый блок под фото и блок под карточку).
- Ошибка API: `error.tsx` с кнопкой «Повторить».
- Нет объявления: `not-found.tsx` с текстом «Объявление не найдено или снято с публикации» и ссылкой «В каталог» на `/`.
