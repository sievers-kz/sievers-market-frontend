# Страница организации

- **Маршрут:** `/account/organizations/[organizationId]` (группа `(site)`, внутри каркаса кабинета; нужны `page.tsx`, `loading.tsx`, `error.tsx`).
- **Доступ:** авторизованный владелец. Проверка входа в браузере, в клиентском компоненте (как `OrganizationsView`): на сервере токен не обновляется. Нет входа (401 после refresh) → `/login?next=<текущий путь>`.
- **Макет:** Figma-кадр «Организация», картинка приложена владельцем к задаче. Это **визуальный ориентир**: структура, состав блоков, иерархия. Макет нарисован в старом стиле (белый фон, рамки): **не копируй его**. Стиль как у всего кабинета: белые карточки `rounded-2xl bg-card` на сером фоне страницы (`docs/pages/account-layout.md`). Размеры подгоняй под сетку 8pt и токены.
- **Контекст:** прочитай `docs/pages/organizations.md` (список, карточка, статусы, опрос, удаление) и `docs/pages/account-layout.md` (каркас). Эта страница открывается из карточки в списке «Мои организации».

## Что входит в задачу
1. Страница организации (чтение, правка трёх полей магазина, удаление).
2. Подпись статуса `verified` меняется с «Подтверждена» на **«Найдена»**, тег `verified` синий. Значение в API остаётся `verified`, меняется только текст и цвет в интерфейсе. Это общий компонент `OrganizationStatusBadge`, поэтому поменяется и в списке «Мои организации».
3. Карточка в списке становится ссылкой на эту страницу.

## Данные (операции API)
Перед началом выполни `npm run gen:api`: в схеме появились `missing_fields` у `OrganizationResponse` и три операции правки. Типы только из `schema.d.ts`, ручные копии запрещены.

| Что | operationId | Примечание |
|---|---|---|
| Организация | `getOrganization` | клиент, `cache: "no-store"`; уже есть в `src/lib/api/organization.ts` |
| Название магазина | `changeOrganizationShopName` | `PATCH /customer/organization/{id}/shop-name`, тело `{ shop_name }` |
| Контактный телефон | `changeOrganizationContactPhone` | `PATCH .../contact-phone`, тело `{ contact_phone }` |
| Контактный email | `changeOrganizationContactEmail` | `PATCH .../contact-email`, тело `{ contact_email }` |
| Удалить | `deleteOrganization` | уже есть; 204 |

Функции правки добавь в `src/lib/api/organization.ts` (имена по `operationId`). Ответ у правок 200 без описанной схемы (в OpenAPI пустая): тело **не читай**, после успеха перечитай организацию `getOrganization`. Расхождение опиши в PR.

Поля `OrganizationResponse`, которые нужны: `id`, `tax_id`, `kind`, `registry_status`, `legal_name`, `legal_address`, `shop_name`, `contact_phone`, `contact_email`, `missing_fields`. `form`, `logo_media_id`, `is_ownership_verified` не показываем.

`missing_fields` это список имён полей (`shop_name`, `contact_phone`, `contact_email`), которые нужно заполнить, чтобы организация могла размещать объявления. Бэкенд считает его сам: **на фронте не пересчитывай по `null` и не дублируй правило**. Список считается всегда, но подсказка показывается только при `verified` (см. «Подсказки»).

## Раскладка
Страница рисуется в колонке контента каркаса: `<main>` и `Container` не добавляй, `AccountPageHeader` не нужен (заголовок страницы это название организации в шапке-карточке). Блоки идут колонкой с зазором 16 (`flex flex-col gap-4`).

1. **Ссылка «Назад»** (`← Назад`, иконка `ArrowLeft` 16 + текст): `Link` на `/account/organizations`, а не `history.back()`, чтобы поведение не зависело от того, откуда пришли. Цвет `text-muted-foreground`, ховер `text-foreground`, высота нажимаемой области не меньше 40.
2. **Шапка-карточка** (`rounded-2xl bg-card p-6`): сверху строка высотой 32 с тегом статуса слева (`OrganizationStatusBadge`) и меню «⋯» справа (`OrganizationActionsMenu`, пункт «Удалить»); ниже строка с аватаром: квадрат 48 `rounded-xl bg-muted` с иконкой `Building2`, справа колонка: `h1` (`text-lg font-semibold`, одна строка, `truncate`) и под ним «БИН 123456789012» / «ИИН 123456789012» (`text-sm text-muted-foreground`, подпись из `formatTaxId`). Заголовок: `shop_name`, иначе `legal_name`, иначе «Организация» (как в карточке списка).
3. **Подсказка** (`OrganizationNotice`), если она есть для текущего состояния. Отдельная карточка `rounded-2xl bg-card p-6` с иконкой слева и текстом, без цветной заливки, чтобы не спорить с тегом.
4. **Карточка «Основная информация»** (только чтение): заголовок секции `h2` (`text-base font-semibold`) и три строки: «Полное наименование организации» (`legal_name`), «БИН» или «ИИН» по `kind` (`tax_id`), «Юридический адрес» (`legal_address`).
5. **Карточка «Данные магазина»**: заголовок секции и три строки с кнопкой «Изменить»: «Название магазина», «Контактный телефон», «Контактный email».

### Строка (`OrganizationFieldRow`)
Подпись `text-sm text-muted-foreground`, под ней значение `text-base` (длинное значение переносится, `break-words`); между строками разделитель `border-b border-border` (у последней строки нет); вертикальные отступы 16. Справа кнопка «Изменить» (`ghost`, цвет `primary`, высота 40, `aria-label` вида «Изменить: Название магазина»). На телефоне кнопка остаётся справа, значение занимает остаток ширины (`min-w-0 flex-1`).
- Пустое значение (`null`): текст «Не указано» (`text-muted-foreground`), кнопка вместо «Изменить» называется **«Заполнить»**.
- Для юридических данных пока нет значения (`pending`, `not_found`): «Появится после проверки» (`text-muted-foreground`). Номер есть всегда.
- Подписи трёх полей магазина всегда с красной звёздочкой (`*` цвета `destructive`, `aria-hidden`, плюс в `aria-label` кнопки слово «обязательное»): они нужны для публикации объявлений. Строки секции «Основная информация» без звёздочек, кнопок «Изменить» у них нет.

## Статусы и подсказки
Тег (`OrganizationStatusBadge`):

| `registry_status` | Подпись | Цвет |
|---|---|---|
| `pending` | «Проверяем» (индикатор крутится, пока идёт опрос) | нейтральный: `bg-muted text-muted-foreground` |
| `verified` | «Найдена» | синий: `bg-cta/10 text-cta` |
| `not_found` | «Не найдена в реестре» | `bg-destructive/10 text-destructive` |

Сейчас `pending` у тега тоже синий: переведи его в нейтральный, иначе два статуса будут одного цвета. Подпись и цвет меняются в `organization-labels.ts` и `organization-status-badge.tsx`; список «Мои организации» получит их автоматически. Остальные тексты со словом «подтверждён…» (форма объявления, `deleteVerified` и др.) **не меняй**, но перечисли их в описании PR: решение по ним за владельцем.

Подсказка (`OrganizationNotice`), показывается одна, в зависимости от состояния:

| Состояние | Текст |
|---|---|
| `pending` | «Проверяем организацию в госреестре. Обычно это занимает несколько секунд.» |
| `not_found` | «Не нашли организацию в госреестре. Проверьте тип и номер. Если ошиблись, удалите её и добавьте заново.» |
| `verified` и `missing_fields` не пустой | «Организация найдена. Заполните данные магазина: они нужны, чтобы размещать объявления.» |
| `verified` и `missing_fields` пустой | подсказки нет |

Подсказка про данные **статичная**: не перечисляет поля, подсветки отдельных полей нет, их показывают звёздочки и «Не указано». Когда `missing_fields` пуст, подсказка исчезает.

## Опрос статуса
Для `pending` работает тот же опрос, что в списке (`useRegistryStatusPolling`: `getOrganization` раз в 3 секунды, до 40 попыток, пауза на скрытой вкладке, остановка при уходе со страницы). Адаптируй хук так, чтобы он не дублировался: ему нужен колбэк с полной `OrganizationResponse`. Когда статус стал другим, страница показывает пришедшие данные целиком (появятся `legal_name`, `legal_address`). После 40 попыток опрос тихо останавливается, в меню «⋯» появляется «Проверить снова» (как в списке).

## Правка поля («Изменить» / «Заполнить»)
Диалог (shadcn `dialog`, образец формы и обработки ошибок: `add-organization-dialog.tsx`), одно поле на диалог, три варианта поверх одного компонента:

| Поле | Заголовок диалога | Ввод | Zod (повторяет описание операции) |
|---|---|---|---|
| `shop_name` | «Название магазина» | `text` | после `trim` и схлопывания пробелов 2–50 символов и хотя бы одна буква |
| `contact_phone` | «Контактный телефон» | `type="tel"`, `inputMode="tel"` | непустая строка; формат проверяет бэкенд (нормализует номер) |
| `contact_email` | «Контактный email» | `type="email"` | непустая строка, email, не длиннее 255 |

В OpenAPI у `shop_name` и `contact_phone` ограничений нет (просто строки), правила взяты из описания операций: опиши это расхождение в PR. Все три поля обязательные, пустое отправить нельзя; кнопка «Сохранить» (`cta`, «Сохраняем…» в процессе) неактивна, пока значение не изменилось или пустое. Поле при открытии заполнено текущим значением.

Успех (200): закрой диалог, перечитай организацию, обнови страницу (подсказка пересчитается по новому `missing_fields`). Ошибки:

| Ответ | Что показать |
|---|---|
| 422 `invalid_shop_name_error` | под полем (`byErrorCode` → `shop_name`), текст из ответа |
| 422 `invalid_phone_format_error` | под полем (`byErrorCode` → `contact_phone`) |
| 422 `{ detail: [...] }` (email) | под полем через `applyApiErrorToForm` |
| 404 `organization_not_found_error` | закрой диалог, показать состояние «Организация не найдена» (ниже) |
| 401 | единый обработчик → `/login?next=...` |
| 5xx, сеть | сообщением формы в диалоге |

Редактирование доступно в любом статусе организации (так сказано в описании операций), поэтому «Изменить» есть и у `pending`, и у `not_found`.

## Удаление
Через меню «⋯» в шапке-карточке (как в списке: `OrganizationActionsMenu`, `DeleteOrganizationDialog`, `DropdownMenu modal={false}`, управляемый диалог). Меню есть только у `pending` и `not_found`; у `verified` меню нет (бэкенд не удаляет подтверждённые организации: 400 `organization_cannot_be_deleted`), место под кнопку остаётся пустым. Успех (204) → `router.replace("/account/organizations")`. 400 → закрой диалог, перечитай организацию, покажи «Подтверждённую организацию удалить нельзя» строкой под шапкой (текст `deleteVerified`; это же поведение, что в списке). 404 → как «не найдена».

## Состояния
- **Загрузка:** `loading.tsx` и `OrganizationDetailSkeleton`: те же карточки (шапка, две секции) с полосками, чтобы страница не прыгала.
- **Организация не найдена** (404 или 422 при кривом id в адресе): внутри колонки кабинета карточка по центру: «Организация не найдена», кнопка «К моим организациям» (`/account/organizations`). Не `notFound()`: данные читаются в браузере. Чужая организация бэкенд отдаёт как ненайденную, это то же состояние.
- **Ошибка загрузки** (сеть, 5xx): сообщение и «Повторить», как в списке.
- **Ошибка маршрута:** `error.tsx`, как у «Мои организации».

## Список «Мои организации»: карточка-ссылка
Вся карточка `OrganizationCard` становится ссылкой на `/account/organizations/<id>`. Не вкладывай кнопку меню в `<a>`: заголовок организации делается `Link` с растянутой областью (`after:absolute after:inset-0`), карточка `relative`, меню «⋯» `relative z-10`, чтобы остаться отдельной целью. Фокус виден (`focus-visible` кольцо `primary`). Ховер карточки: лёгкая тень, без смены цвета рамки. После возврата со страницы организации список перечитывается (он и так читается при монтировании).

## Адаптивность и доступность
Проверь 375, 768, 1280, 1440. На телефоне блоки в одну колонку, диалог по ширине экрана с отступами. Все действия доступны с клавиатуры; у кнопок «Изменить» осмысленный `aria-label`; диалоги возвращают фокус на кнопку, открывшую их. Контраст серого текста не ниже 4.5:1.

## Что не делаем
Публичная страница организации и каталог организаций (поставщиков, контрагентов): отдельный экран, нужен свой endpoint, сейчас его нет. Логотип, `form`, подтверждение владения (`is_ownership_verified`), отдельный пункт «Редактировать» в меню, массовая правка всех полей одной формой, переименование значения `verified` в API.

## Что отличается от макета
Стиль карточек: серый фон страницы и белые карточки вместо белого фона с рамками (решение по всему кабинету). Тег статуса и его цвета, подсказка про данные, «Заполнить» для пустых полей, звёздочки у обязательных полей, состояние «не найдена»: в макете их нет. Меню «⋯» у подтверждённой организации не показывается. Отметь это в описании PR.
