# Каталог организаций

- **Маршрут:** `/organizations` (`src/app/(site)/organizations/`), параметры URL `q` и `page`.
- **Доступ:** все, без авторизации.
- **Макет:** Design-артефакт «Каталог организаций» (карточки в сетке, поиск на всю ширину контейнера). Визуальный ориентир: размеры по сетке 8 и токенам, hex в компонентах не писать.
- **Рендер:** Server Component, всё состояние в URL. Клиентская часть только у формы поиска.

## Зачем
Покупатель видит, у кого можно купить: список организаций, которые прошли проверку по реестру и чьё владение подтвердил администратор. Пока это витрина: страницы организации в этом PR нет.

## Предусловия
- Бэкенд PR #254 влит и задеплоен (`GET /api/v1/customer/organizations/catalog`).
- `npm run gen:api` выполнен: в `schema.d.ts` есть `getOrganizationsCatalog` и `OrganizationCardResponse`.

## Данные
| Что | operationId | Где | Примечание |
|---|---|---|---|
| Страница каталога | `getOrganizationsCatalog` | сервер | `GET /customer/organizations/catalog`, query: `q` (≤ 100 символов), `page` (≥ 1), `limit` (1–50). Ответ `PaginatedResponse[OrganizationCardResponse]`: `items`, `total`, `page`, `pages` |

Поля карточки: `id`, `name`, `logo_media_id` (может быть `null`), `listings_count` (число активных объявлений).

- Функцию назвать `getOrganizationsCatalog`, положить в `src/lib/api/organization.ts`, через `apiFetch`.
- Кэш: запрос зависит от `q` и `page`, ставим `next: { revalidate: 60 }`. Каталог меняется только когда админ подтверждает организацию, секундная свежесть не нужна.
- Размер страницы **16** (`ORGANIZATIONS_PAGE_SIZE = 16` константой рядом с компонентами, в `limit` передаём её). 16 = 4 ряда по 4 колонки на десктопе и 8 рядов по 2 на телефоне, без «висячего» ряда на обоих брейкпоинтах. Если появится промежуточный брейкпоинт с 3 колонками, переходим на 24.

## Параметры URL
- `q`: строка, обрезать пробелы по краям; пустая или длиннее 100 символов (обрезать до 100) не передаётся в API.
- `page`: целое ≥ 1; некорректное значение → 1.
- Любое изменение `q` сбрасывает `page` на 1.
- Разбор и сборка ссылки в `components/organizations/search-params.ts` (`parseOrganizationsParams`, `buildOrganizationsHref`), по образцу `components/catalog/search-params.ts`.

## Структура экрана
Всё внутри `<Container>`, mobile-first.
1. **Заголовок** «Организации» (`h1`) и под ним «Найдено: N» (`total`, склонение «организация / организации / организаций»; хелпер по образцу `format-found.ts`). При пустом результате строку «Найдено» не показываем.
2. **Поиск** на всю ширину контейнера: поле (`Input`, `type="search"`, `maxLength=100`, placeholder «Название организации») и кнопка «Найти» (`variant` на токене `cta`, главное действие). Это обычная `<form method="get">`: отправка пишет `?q=` через `router.push`; поле заполнено текущим `q`. Кнопки сброса нет: пустой запрос и «Найти» возвращают полный список.
3. **Сетка карточек:** 2 колонки на телефоне (`gap-4`), 4 колонки с `lg` (`lg:gap-6`).
4. **Пагинация** под сеткой: общий `components/common/pagination.tsx` с `hrefFor`; не показывать при `pages <= 1`.

### Карточка организации (`OrganizationCard`)
- Белая карточка (`rounded-2xl bg-card`), внутренний отступ `p-4`, с `lg` `p-6`.
- Сверху зона логотипа на белом фоне: горизонтальная зона фиксированной высоты (128 px на телефоне, 160 px с lg), логотип `object-contain`; заглушка 64 px.
  - Публичного URL логотипа по `logo_media_id` пока нет (ручка выдачи presigned URL для чтения не реализована). **Всегда рисуем заглушку:** нейтральный круг/квадрат на `bg-muted` с иконкой `Store` (lucide) или первой буквой названия. Когда URL появится, это единственное место, которое поменяется; `logo_media_id` в разметке не использовать.
- Название: одна строка с обрезкой многоточием (`truncate`), `title={name}` для полного текста, `text-base font-semibold`, выровнено по левому краю.
- Под названием, через 8 px, счётчик зелёным (`text-primary`): «N объявлений» с русским склонением (1 объявление, 2–4 объявления, 5+ и 11–14 объявлений). Ноль показываем как «Нет объявлений» серым (`text-muted-foreground`).
- В этом PR карточка **не кликабельна** (страницы организации и публичной ручки по `id` нет). Кнопку «Подробнее» из макета не рисуем, но оставляем раскладку так, чтобы низ карточки можно было закрепить (`flex flex-col`, блок с кнопкой `mt-auto`), когда появится деталка. Это отличие от макета отметить в описании PR.
- Бейджей («Проверена», уровни доверия) нет: в каталоге все организации одного уровня.

## Состояния
- **Загрузка:** `loading.tsx` со скелетоном: заголовок, поле поиска и `ORGANIZATIONS_PAGE_SIZE` карточек-заглушек в той же сетке.
- **Пусто, без запроса:** «Пока нет организаций в каталоге» (каталог пуст, пока админ никого не подтвердил). Без кнопок.
- **Пусто, с `q`:** «Ничего не найдено по запросу «…»» и ссылка «Сбросить поиск» на `/organizations`. Текст запроса показывать как текст, не как HTML.
- **Ошибка API:** `error.tsx` с сообщением и кнопкой «Повторить» (как у соседних маршрутов).
- **Страница за пределами:** если `page > pages` и `total > 0`, `notFound()`. При `total = 0` страница 1 показывает пустое состояние, а не 404.
- **Нет авторизации:** не требуется, любое состояние сессии не влияет на страницу.

## Ограничения и вне рамок
- Фильтров (регион, вид деятельности, бренд) и сортировки нет: поиск по названию достаточно для MVP.
- Страницы организации, рейтингов, бейджей, регионов нет.
- Логотипы: заглушка, пока бэкенд не отдаёт URL.
- Каталог будет пуст на проде, пока администратор не создаст право `verify:organization` и не подтвердит хотя бы одну организацию (операции на стороне бэкенда).
- Поиск идёт по `shop_name` и `legal_name`; в карточке показывается `name` (название магазина, а если его нет, юридическое). Совпадение по юридическому названию может показать организацию, у которой в карточке другое имя; так задумано, это не ошибка.

## Метаданные и SEO
- `metadata`: title «Организации», description коротко про каталог проверенных организаций. Canonical `/organizations` без параметров (страницы поиска индексировать не нужно: у `q` `robots: noindex`). Добавить маршрут в `sitemap.ts`.
