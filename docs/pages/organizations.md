# Мои организации

- **Маршрут:** `/account/organizations` (группа `(site)`, нужны `page.tsx`, `loading.tsx`, `error.tsx`).
- **Доступ:** только авторизованный пользователь. Проверка в браузере, в клиентском компоненте (как блок пользователя в шапке и `ListingCreateGate`): на сервере токен не обновляется. Гостя отправь на `/login?next=/account/organizations`.
- **Макет:** нет. Сделай по описанию в стиле остальных экранов (светло-серый фон, белые карточки со скруглением, `Container`). Владелец продукта нарисует макет позже; тексты и состояния ниже — рабочее предложение, все подписи держи в `src/components/account/organization-labels.ts`, чтобы менять в одном месте.
- **Контекст:** прочитай `docs/pages/organizations-migration.md` (модель организаций, статусы, коды ошибок). Эта страница — PR 2.

## Данные (операции API)
| Что | operationId | Примечание |
|---|---|---|
| Список | `getOrganizations` | клиент; `OrganizationListResponse[]` |
| Добавить | `createOrganization` | тело `{ kind, tax_id }`, ответ 201 `{ id, registry_status }` |
| Один | `getOrganization` | опрос статуса |
| Удалить | `deleteOrganization` | 204 |

Функции кладём в `src/lib/api/organization.ts` (имена по `operationId`). Типы только из `schema.d.ts`, ручные копии запрещены.

### Карточка организации
Все карточки устроены **одинаково**, различает их только тег статуса. Подсказок, разделителей и кнопок в карточке нет. Белая карточка `rounded-2xl bg-card p-6`, сетка внутри (сверху вниз):
1. Верхняя строка (`flex items-center justify-between`, высота 32): слева **тег статуса**, справа кнопка-меню «⋯» (`ghost`, 32×32, `aria-label="Действия"`; у `verified` её нет, место остаётся).
2. Ниже строка с аватаром: квадрат 48 `rounded-xl bg-muted` с иконкой `Building2` (логотип появится позже, пока всегда иконка), справа колонка:
   - **заголовок** (`text-base font-semibold`): `shop_name`, иначе `legal_name`, иначе «Организация» (пока нет данных реестра: `pending` и `not_found`). **Одна строка**, длинное название обрезается `truncate` с многоточием, на вторую строку не переносится (`title` с полным названием не нужен);
   - строка под ним (`text-sm text-muted-foreground`): «ИИН 123456789012» или «БИН 123456789012» по `kind` (номер обязателен, строка есть всегда). Слов «ИП» и «Юрлицо» отдельно не пишем.
3. Вся карточка станет ссылкой на страницу организации, когда страница появится. Сейчас не ссылка.

Меню «⋯» (shadcn `dropdown-menu`, уже есть в проекте): сейчас только «Удалить» (цвет `destructive`, иконка `Trash2`), открывает подтверждение (раздел «Удаление»). Для `verified` меню нет. Пункт «Редактировать» добавим вместе со страницей организации, сейчас его нет, чтобы не было мёртвого пункта. Если опрос остановился (см. ниже), в меню `pending` добавляется «Проверить снова».

### Статусы
Только тег (цвет токенами, текст обязателен: статус не передаётся одним цветом).
| `registry_status` | Тег |
|---|---|
| `pending` | «Проверяем» (с индикатором) |
| `verified` | «Подтверждена» |
| `not_found` | «Не найдена в реестре» |

Пояснений текстом в карточке нет: тег сам говорит состояние, причину и что делать покажем на будущей странице организации.

### Опрос статуса
Для каждой карточки со статусом `pending`: `getOrganization(id)` раз в 3 секунды, пока статус не станет другим. Ограничения:
- не больше 40 попыток (около двух минут); после этого опрос останавливается молча, тег остаётся «Проверяем», а в меню «⋯» появляется пункт «Проверить снова» (запускает опрос заново);
- опрос останавливается при уходе со страницы (cleanup в эффекте) и когда вкладка скрыта (по желанию, если это дёшево);
- при 404 (организацию удалили в другой вкладке) убери карточку из списка;
- смена статуса обновляет карточку без перезагрузки списка.
Если статус `pending` держится дольше ~15 минут, бэкенд перестаёт повторять проверку и статус остаётся `pending` до ручной проверки (backend#228). Для пользователя это то же состояние «Проверяем» с пунктом «Проверить снова», отдельного состояния не делаем.

## Форма «Добавить организацию»
Поля:
1. **Тип** — две плитки-радио (`TileRadioGroup`, он уже есть в проекте и принимает только `value` и `label`, менять его не нужно): «ИП (ИИН)» (`kind: "individual"`) и «Юридическое лицо (БИН)» (`kind: "company"`). Компонент лежит в `src/components/onboarding/`, который удаляется в PR 1: **перенеси `tile-radio-group.tsx` в `src/components/common/` в PR 1** (импорты поправь), там он и используется. По умолчанию ничего не выбрано.
2. **Номер** — поле `tax_id`, подпись «ИИН» или «БИН» по выбранному типу (пока тип не выбран, «ИИН / БИН»). Только цифры, ровно 12 (`inputMode="numeric"`, `maxLength=12`). Zod: `^\d{12}$` (как `CreateOrganizationRequest`), сообщение «Введите 12 цифр».
3. Кнопка «Добавить» (`cta`, во время запроса «Добавляем…», отключена). Пока тип не выбран или номер неполный, кнопка неактивна.

Успех (201): закрой диалог, добавь организацию в начало или конец списка (бэкенд отдаёт список в порядке добавления, добавляй в конец) со статусом `pending` и запусти опрос. Id и статус бери из ответа, остальные поля подтянутся первым ответом `getOrganization`.

### Ошибки формы
| Ответ | Что показать |
|---|---|
| 409 `organization_already_exists_error` | под полем номера (ошибка `tax_id`): «Организация с таким номером уже добавлена» |
| 422 `{ detail: [...] }` по `tax_id` | под полем номера (через `applyApiErrorToForm`) |
| 401 | единый обработчик → `/login?next=/account/organizations` |
| 5xx, сеть | сообщением формы в диалоге |

Ошибки без поля показывай сообщением формы (`showFormError`).

## Удаление
Пункт «Удалить» в меню «⋯» открывает подтверждение (shadcn `alert-dialog`, `npx shadcn add alert-dialog`): «Удалить организацию? После удаления номер можно добавить заново.» и кнопки «Отмена», «Удалить».
- успех (204) → карточка исчезает;
- 400 `organization_cannot_be_deleted` (организацию успели подтвердить) → закрой диалог, обнови карточку (`getOrganization`), покажи сообщение «Подтверждённую организацию удалить нельзя»;
- 404 → карточка исчезает без ошибки.
