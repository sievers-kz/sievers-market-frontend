# Поверхности и общий стиль (переход с «плавающих карточек» на белую страницу)

- **Маршруты:** все существующие экраны: каталог, объявление, подача объявления, кабинет (`/account/*`), вход и регистрация.
- **Доступ:** без изменений.
- **Макеты:** Design-холст https://claude.ai/artifact/DMH4oYihFNUEx7bHvumpSt (итоговый артборд «6. Мои объявления: белый, рамки у панелей, тени у карточек»). Это визуальный ориентир, размеры по сетке 8pt и токенам.
- **Данные и API:** не затрагиваются. Только стили и разметка контейнеров.

## Зачем

Сейчас страница светло-серая (`bg-muted` на каждом `<main>`), а блоки белые и «плавают» поверх неё. Из-за этого на экране много одинаковых объектов без иерархии. Новый подход: страница белая, структуру задают рамки панелей, а объекты контента отделяет мягкая тень. Решение принято без жёсткого утверждения: если в коде не зайдёт, правим значения токенов, а не структуру.

## Что менять не нужно

Раскладки, размеры колонок, тексты, поведение, значения `primary` (#076852) и `cta` (#1C608A). Новых экранов не рисовать, тёмную тему не делать. Всё, что ниже, это цвет фона, рамка, тень и скругление.

## 1. Токены (`src/app/globals.css`)

Изменить значения:

| Токен | Было | Станет | Зачем |
|---|---|---|---|
| `--foreground`, `--card-foreground`, `--popover-foreground`, `--secondary-foreground` | `#171717` | `#1B2B26` | основной текст нового стиля |
| `--border` | `#e5e7eb` | `#E6E9E8` | рамка панелей |
| `--muted`, `--secondary` | `#f3f4f6` | `#F3F5F4` | нейтральный тонированный серый (плитки, заглушки фото, неактивные вкладки) |
| `--accent` | `#e6f2ef` | `#E8F3F0` | подложка активного пункта сайдбара |
| `--accent-foreground` | `#054a3a` | `#076852` | текст активного пункта |

`--input` (рамка полей ввода) и `--muted-foreground` не трогать. После правки пройти по местам, где используются `accent` и `accent-foreground` (`guest-actions.tsx`, `subcategory-nav.tsx`, `account-nav-link.tsx`, кнопки и меню в `ui/`), и убедиться, что ничего не стало нечитаемым.

Добавить новые токены и подключить их в `@theme inline`:

```css
:root {
  --shadow-card: 0 1px 2px rgba(27, 43, 38, 0.06), 0 4px 12px rgba(27, 43, 38, 0.08);
  --shadow-card-hover: 0 2px 4px rgba(27, 43, 38, 0.08), 0 8px 20px rgba(27, 43, 38, 0.12);

  /* Янтарная плашка-предупреждение (понадобится в «Мои объявления» и на странице организации) */
  --warning: #fdf3dc;
  --warning-border: #f0dca8;
  --warning-foreground: #5c3b00;
}
@theme inline {
  --shadow-card: var(--shadow-card);
  --shadow-card-hover: var(--shadow-card-hover);
  --color-warning: var(--warning);
  --color-warning-border: var(--warning-border);
  --color-warning-foreground: var(--warning-foreground);
}
```

После этого доступны утилиты `shadow-card`, `shadow-card-hover`, `bg-warning`, `border-warning-border`, `text-warning-foreground`. Если `@theme inline` в нашей версии Tailwind не принимает тени так, как написано выше, сделай по документации Tailwind 4 из `node_modules` и опиши решение в PR.

Правило без исключений: цвета, рамки и тени в компонентах только через токены. Никаких hex, `bg-white`, `bg-black`, `shadow-[...]`. Это же условие для будущей тёмной темы (там подменяются значения токенов, а не разметка).

## 2. Четыре вида поверхностей

Каждый блок на странице относится ровно к одному виду.

**Страница.** `bg-background` (белая). `<main>` без `bg-muted`.

**Панель.** Блок, который организует страницу или содержит элементы управления: шапка и блок фильтров, секции формы, текстовые блоки страницы объявления, заглушка «нужна организация», карточка входа. Класс: `rounded-2xl border bg-card`, внутренний отступ 24 (`p-6`), у компактных 16 (`p-4`). Тени нет.

**Карточка-объект.** Повторяющийся объект-сущность, который можно открыть или выбрать: карточка объявления (каталог, превью), карточка организации. Класс: `rounded-2xl bg-card shadow-card`. Рамки нет. Если карточка кликабельна (ссылка), на hover `shadow-card-hover`, переход `transition-shadow`. Фокус (`focus-visible:ring-2 ring-ring`) остаётся как есть.

**Сайдбар.** Сайдбар кабинета и блок подкатегорий каталога: без фона, без рамки, без тени, прямо на белой странице. Выделение только у активного пункта: `bg-accent text-accent-foreground`, при наведении `hover:bg-muted`.

Не менять: шапку сайта (`border-b bg-background`), окна и выпадающие списки shadcn (`dialog`, `alert-dialog`, `popover`, `select`): у них уже обводка и тень, они нужны поверх страницы.

## 3. Что править по экранам

**Все `<main>` с `bg-muted`** заменить на `bg-background` (или убрать класс): `catalog/[categoryId]/{page,loading,error,not-found}.tsx`, `listing/[listingId]/{page,loading,error,not-found}.tsx`, `listings/new/{page,loading,error}.tsx`, `(auth)/layout.tsx`, `AccountShell`. Перед правкой выполни `grep -rn "bg-muted" src/app src/components` и пройди все совпадения: `bg-muted` в плитках, заглушках фото, чипах и бейджах остаётся.

**Каталог.**
- `CatalogListHeader`: панель (`border`, `p-4`; сейчас `bg-card` без рамки).
- `SubcategoryNav`: сайдбар (убрать `rounded-2xl bg-card p-2 lg:p-4`; на телефоне строка кнопок остаётся). Активный пункт `bg-accent`.
- `ListingCard` / `ListingCardView`: карточка-объект (`shadow-card`, hover `shadow-card-hover` на `Link`; убрать `hover:shadow-md`). Превью в форме объявления использует ту же `ListingCardView`, поэтому получает тень само.
- `ListingCardSkeleton`, `ListingGridSkeleton`, `CatalogEmpty`, `CatalogPagination`: привести к своему виду (скелетон карточки как карточка-объект, пусто и пагинация как панель). Заглушка повторяет настоящий блок, чтобы страница не прыгала.

**Страница объявления.** `ListingTitleCard`, `ListingSummaryCard`, `ListingAttributes` (внешний блок), `ListingDescription`: панели. Плитки характеристик внутри (`bg-muted rounded-xl p-4`) остаются. Фото в галерее (`rounded-2xl bg-muted`) остаётся без рамки.

**Подача объявления.** `FormSection`: панель. Сейчас у неё `border border-transparent`, замени на `border` (цвет по умолчанию `--border`); состояние ошибки `border-destructive` сохранить. `OrganizationRequired`: панель. Проверь `OrganizationSelect`, `CatalogPicker`, `ImageUploader`, `ListingCreateGate`, `ListingCreateFlow`: каждый блок с `bg-card` отнести к одному из видов.

**Личный кабинет.**
- `AccountShell`: у `<aside>` убрать `lg:rounded-2xl lg:bg-card lg:p-4`, сайдбар становится плоским. Колонка контента как была.
- `AccountNavLink`: на телефоне (вкладки) неактивная вкладка `bg-muted`, активная `bg-accent`, пометка «Скоро» читается на обоих фонах; с `lg` пункт прозрачный, как сейчас. Проверь контраст пометки «Скоро» на `bg-muted` и при необходимости задай ей `bg-card`.
- `AccountPageHeader`: комментарий «на сером фоне» обновить на «на белом».
- `OrganizationCard`: карточка-объект (`shadow-card`). `OrganizationsView`, `OrganizationsListSkeleton`, `account/organizations/error.tsx`: привести к тому же.

**Вход и регистрация.** `AuthCard`: панель (`border`, без тени). Страница белая, карточка по центру с рамкой.

**Общие компоненты.** `SkeletonCard` получает два варианта (`panel` и `card`) с теми же классами, что у настоящих поверхностей; все скелетоны переключить на подходящий вариант. Полоски `Skeleton` не менять.

## 4. Порядок работы и PR

Три PR в `dev`, по одному на тему, начинать с первого:
1. `feature/style-surfaces-tokens`: токены, `SkeletonCard`, каталог (это эталон нового вида; сверить руками).
2. `feature/style-surfaces-listing`: страница объявления и подача объявления.
3. `feature/style-surfaces-account-auth`: кабинет, вход и регистрация.

В каждом PR обновить спецификации своих экранов в `docs/pages/` (заменить «светло-серый фон, белые блоки» на ссылку на этот файл) и `docs/STATUS.md`. Упоминания в `catalog.md`, `listing.md`, `listing-create.md`, `polish.md`, `account-layout.md`, `auth.md` найди через `grep -n "серый" docs/pages/*.md`.

## 5. Приёмка

- На каждом экране нет серого фона страницы, нет блока без рамки и без тени (кроме сайдбаров), нет двух разных видов поверхностей у одного блока.
- Тень не обрезается: проверь родителей карточек с `overflow-hidden` / `overflow-x-auto` (строка вкладок кабинета, сетка карточек) и зазоры между карточками (16 и больше).
- Экраны сверены в ширинах 375 и 1280, включая загрузку (`loading.tsx`), ошибку и пустое состояние.
- `npm run typecheck`, `lint`, `build` проходят; в компонентах нет hex и `bg-white`.
- В описании PR: какие блоки отнесены к какому виду там, где правило неочевидно, и что отличается от макета.

## 6. Заметки

- Рамка полей ввода (`--input` `#e5e7eb`) по контрасту слабая относительно WCAG для границ элементов управления. В этот PR не входит; если захочешь усилить, это правка одного токена.
- Тёмная тема: не сейчас. Тени на тёмном фоне почти не видны, поэтому там уровни обычно показывают разной яркостью фона (страница темнее, карточка светлее); подмена значений `--background`, `--card`, `--border`, `--shadow-card` без правки разметки возможна только при соблюдении правила про токены.
- Статичная тень по умолчанию принята сознательно (так делают маркетплейсы). Альтернатива «рамка и тень на hover» меняется заменой токена и классов карточки-объекта, структуру не затрагивает.
